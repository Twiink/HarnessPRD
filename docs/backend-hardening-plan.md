# 后端一致性与运行保障实施计划

2026-10-15，按已确认的第二轮审查方案实施。保留单机单进程、SQLite、`src/apps`、`/api`、既有数据和前端；不新增依赖。

## 实施顺序

1. 先补回归：正文变更、来源快照、基线与质量失效、输入输出契约、超时/容量/迟到写入、读锁、健康降级与资源缺失。
2. 修复一致性：统一正文 hash 和状态规则，提交时固定来源；只读快照收集导出材料后再压缩；已有正文显式清空返回 422，省略字段保留。
3. 完善运行保障：任务总时限 1200 秒、模型调用 180 秒、流空闲 120 秒、等待队列 100；超时先撤销所有权；进度按 250ms 或 4KiB 合并；持续调度失败 30 秒降级。
4. 收紧边界：严格校验已知嵌套字段并保留扩展字段，统一 Agent 输出和模型文本；应用级共享模型并发；启动验证必需资源，锁忙映射可重试 503。
5. 整理职责：增加 bootstrap、api/compat，services 按 sessions/documents/generation/conversations 分组；纯规则下沉 domain；资源加载脱离 services；AST 检查依赖方向。
6. 固化验证：pytest、Ruff、format、锁文件、AST 边界检查、现有 Mypy；增加 CI、备份恢复与排障说明。

## 重构约束

- 先保护行为，再逐组移动；修复重复、反向依赖和隐式事务，不引入通用框架或额外包装层。
- API 只转换协议，应用服务持有写事务；domain 不依赖 HTTP、数据库或模型框架；Agent 不依赖 services。
- 旧路径保持兼容，调用共享用例、校验与资源限制；历史事件首轮不自动删除。
- 各独立实现部分在原位置完成并验证后，统一迁移导入与测试路径，避免并行重命名。

## 验收

所有既有行为回归与新增故障场景通过；长文档回放正文、顺序和终态一致；迟到执行者无法写入；工作区无前端或依赖变化。真实供应商联调与生产负载评估不使用付费调用代替本地确定性测试。

## 实施结果

2026-10-15：上述步骤已完成。主要变更按职责分组如下：

- `bootstrap/` 与 `api/compat/`：集中资源装配、启动验证、关闭和旧路径适配；API 写事务移入 `services/sessions/commands.py`。
- `services/sessions/`、`documents/`、`generation/`、`conversations/`：会话展示、文档查询、版本写入、导出和 Prompt 构建分离；移除原平铺 Service 及资源转发模块。
- `domain/`、`core/resources/`：共享嵌套输入、Review、内容身份和质量规则，统一 JSON 解析与文本块转换；Agent 不再反向依赖 services。
- `runtime/`、`llm/`、`db/`：时限、真实调用容量、所有权撤销、有限队列/恢复、进度批处理、只读快照和健康诊断。每次尝试新增兼容 snapshot，已有客户端可正确重置重试草稿。
- `.github/workflows/backend.yml`、`scripts/sqlite-backup.py`、`docs/backend-operations.md`：自动检查、SQLite API 在线备份恢复和运维说明。

独立复核补充修复了优化/恢复丢失来源、导出字节与 hash 不一致、跨会话任务指针、无效基线时间戳、旧数据查询隐式写锁、空 Skill 绑定和自定义 Skill 的固定目录依赖。
