# 交付质量 — 测试验收

## 测试准备

验收范围：

- 澄清状态与生成前警告（澄清页顶栏，非折叠底栏）
- 交付守卫（前后端 `generate_prd` / 基线相关 artifact）
- `quality_gate` 与质量报告 UI
- 需求基线确认与撤销
- `derived_from` 与过期提示
- 接口文档 / 提示词 Review Agent
- 交付包 ZIP 导出

环境要求：

- `backend/.env` 配好 LLM
- 后端 `uvicorn main:app --reload` 已启动
- 前端 `npm run dev` 已启动
- 浏览器可访问 `/v2` 与 `/v2/list`

**不在本次验收范围：** LangGraph/MCP、REQ-ID、PRD diff、Golden Eval CI、`team.yaml`、下游自动 Rewrite、v1 `/`。

---

## 一、澄清状态与生成前警告（01 篇）

### 1. 澄清页展示

1. 主路径填表 → 进入澄清
2. AI 回复后观察顶栏状态 badge

预期：

- AI 提出编号问题时，顶栏显示「澄清进行中 · N 个待确认」
- **无**底栏待确认问题折叠面板
- **「生成 PRD ⚠」可点**

### 2. 警告确认放行

1. 在 AI 仍含未回复问题的状态下点击「生成 PRD」
2. 在 confirm 中选「取消」
3. 再次点击并选「仍要生成 PRD」

预期：

- 第一次 cancel 不进入 sync / 不创建 Job
- 第二次确认后走现有 syncSummary → Diff 或 Job 流程
- confirm 文案列出待确认问题，中文可读

### 3. 回复后状态更新

1. AI 提问后，用户在输入框回复
2. 观察顶栏（在下一轮 AI 回复前）

预期：

- 末条为用户消息时，不因上一轮 AI 问题再次强制 confirm（除非仍有 warnings）
- 若 AI 新一轮仍提问，顶栏再次琥珀

### 4. 后端兜底

1. summary 正常 → 创建 PRD Job

预期：成功，**不因**澄清未完成 400

2. 无 summary（异常 mock）→ 创建 PRD Job

预期：400，detail 含「缺少结构化需求摘要」

### 5. 非 structured 路径

`entryMode=prd` 导入 PRD 进入 review

预期：无澄清状态 UI（不适用）

| # | 用例 | 结果 |
|---|------|------|
| 1 | 顶栏澄清状态（无底栏折叠面板） | ☐ |
| 2 | 未澄清 confirm 放行 | ☐ |
| 3 | 回复后状态更新 | ☐ |
| 4 | 后端仅缺 summary 400 | ☐ |
| 5 | 导入路径无澄清状态 | ☐ |

## 二、结构校验与质量报告（02 篇）

### 1. PRD gate 写入

1. 正常走通生成 PRD
2. 打开版本侧栏或 API 查看 current 版本 metadata

预期：

- 存在 `quality_gate`
- 含 `score`、`checks` 数组
- 正常 PRD 多数 high 项 passed

### 2. 质量报告 UI

1. 在 `review-prd` 查看「质量报告」区域

预期：

- 与 Review 意见分区清晰
- 失败项显示 detail

### 3. 故意缺陷（可选）

手改 PRD 删掉「## 6. 项目范围」整段 → debounce 保存 → 手动触发 gate 或重新 optimize 完成

预期：`prd.section.scope` 或等价 check failed

### 4. api-docs / prompts

各生成一次，检查 metadata 与 UI

预期：均有 `quality_gate`；prompts 的 MVP 数量 check 在缺 PRD 时 skipped 或合理

### 5. PRD Rewrite 路径

触发 Review 不通过 → Rewrite 完成

预期：gate 针对 **最终稿**；非 draft_v1

| # | 用例 | 结果 |
|---|------|------|
| 5 | PRD metadata.quality_gate | ☐ |
| 6 | review 页质量报告 | ☐ |
| 7 | api-docs / prompts gate | ☐ |
| 8 | Rewrite 后 gate 对最终稿 | ☐ |

## 三、需求基线（03 篇 · 第一节）

### 1. 未确认不可下游

1. PRD 生成完成，**不**点确认
2. 尝试「生成接口文档 →」

预期：按钮 disabled 或等同拦截；tooltip / banner 说明

### 2. 确认后解锁

1. 点击「确认需求基线」
2. 再点「生成接口文档 →」

预期：Job 正常创建；进入 generating-api-docs

### 3. 撤销确认

1. 确认基线后编辑 PRD 任一字符，等待 debounce 保存
2. 或：重新生成 PRD（新版本）

预期：基线失效；banner 恢复；下游按钮再次 disabled（直至重新确认）

### 4. 后端对齐

未确认基线时 `POST /api/jobs` artifact=api-docs

预期：`400`，中文 detail

### 5. 跳过 API 路径

确认基线后点「跳过接口文档，直接生成提示词」

预期：同样要求已确认；跳过后 prompts metadata 可含 `api_docs_skipped`

| # | 用例 | 结果 |
|---|------|------|
| 9 | 未确认 disable 下游 | ☐ |
| 10 | 确认后 unlock | ☐ |
| 11 | 手改 / 重生撤销基线 | ☐ |
| 12 | 后端 api-docs 400 | ☐ |

## 四、上下游过期提示（03 篇 · 第二节）

### 1. derived_from 写入

1. 确认基线 → 生成 api-docs 完成
2. 查 api-docs current 版本 metadata

预期：`derived_from.prd_version_no` 等于确认时 PRD 版本号

### 2. 过期 banner

1. 手改 PRD 或重新生成使 PRD 版本号升高（或内容变而 version 升）
2. 打开 `review-api-docs`

预期：amber 过期提示；文案含 PRD 新旧版本号

### 3. 重新生成

点 banner「重新生成接口文档」（若提供）

预期：新 Job；新 derived_from 指向新 PRD current

| # | 用例 | 结果 |
|---|------|------|
| 13 | derived_from 正确 | ☐ |
| 14 | PRD 变更后过期 banner | ☐ |

## 五、下游 Review Agent（03 篇 · 第三、四节）

### 1. 接口文档 Review

1. 生成 api-docs，观察 Stepper / phase
2. 完成后查看 review 页

预期：

- 有 reviewing 阶段提示（非长时间无反馈）
- `metadata.review` 存在；UI 展示 summary / issues
- 正文完整，不因 review 失败而清空

### 2. 提示词 Review

同上，artifact=prompts

预期：同上

### 3. 无 Rewrite

Review 故意不通过（可用极短 PRD 抽测）

预期：**无** rewriting phase；无自动第二次生成

| # | 用例 | 结果 |
|---|------|------|
| 15 | api-docs Review UI + metadata | ☐ |
| 16 | prompts Review UI + metadata | ☐ |
| 17 | 无自动 Rewrite | ☐ |

## 六、交付包导出（03 篇 · 第五节）

### 1. 导出内容

1. 三文档均有内容 → 点「导出交付包」
2. 解压 ZIP

预期：

- 含 `PRD.md`、`Prompts.md`；有 api-docs 则含 `API-Docs.md`
- 含 `manifest.json`、`README.md`
- manifest 含各文档 `version_no`、`quality_gate.passed`、`review.summary`（若有）
- README 中文，说明阅读顺序

### 2. 部分缺失

仅 PRD、无 api-docs

预期：仍可导出；manifest 如实；README 说明缺失项

### 3. 空交付

全空文档

预期：导出按钮 disabled 或导出失败提示

| # | 用例 | 结果 |
|---|------|------|
| 18 | ZIP 结构与 manifest | ☐ |
| 19 | 缺 api-docs 仍可导出 | ☐ |
