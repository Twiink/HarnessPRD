# 文档结构校验与质量报告提示词

点击此处可复制本篇提示词

本篇在 PRD、接口文档、提示词三类文档 **Job 完成后** 运行确定性结构校验（`quality_gate`），结果写入版本 `metadata`，并在 review 页展示 **质量报告** 面板。PRD 在 Rewrite 完成后同样执行 gate，**不增加第二次 LLM Review**。

## 使用场景

这份提示词用于 harnessprd 项目 `backend/services/` 与 `frontend/` 改造生成后质检与展示。

**前置条件**：Generation Job、`document_version_service`、`DocumentReviewWithVersions` 已可用；PRD 已有 Review Agent。

**现状问题：** Review Agent 覆盖语义层（漏项、矛盾、编造），但无法校验格式层（章节是否齐全、MVP 是否为表格、接口文档分区是否完整等）。当前 Job 完成后仅有 `metadata.review`（且仅 PRD 有），用户看不到结构是否达标。

**改造后的质检链路：**

```
Job 完成（最终正文）
  → run_quality_gate(doc_type, content)
  → metadata.quality_gate 写入 document_versions
  → review 页 QualityReportPanel 展示
```

**本次不做：**

- 就绪度、基线确认、下游 Review Agent、交付包
- 用 LLM 做结构校验（**全部规则代码实现**）
- 校验失败自动触发 Rewrite 或重新生成（仅 **报告 + 展示**）
- 改造 v1 `App.tsx`

### 一、功能目标

- 新增 `quality_gate_service.py`（或 `services/quality_gate.py`）：按文档类型跑检查项
- Job 完成写入 current 版本时，合并 `metadata.quality_gate`
- PRD / api-docs / prompts 三条生成线（含 optimize Job 完成）均调用 gate
- 前端 `QualityReportPanel`：复用或并列 `ReviewResultPanel`，展示 passed、score、checks 列表
- PRD 流程：Review → [Rewrite] → **gate** → done（gate 不调 LLM）

### 二、要解决的问题

Review Agent 负责 **语义审查**，但无法覆盖以下 **格式与结构** 问题：

- 章节标题是否齐全、MVP 是否为表格
- 接口文档是否包含「核心 / 边缘」分区
- 提示词套件 5 类章节是否完整

上述问题用 **确定性规则** 更稳定、更快、可单测，且不消耗 LLM token。当前 Job 完成后用户只能看到 Review 结果，缺少格式层反馈。

### 三、代码结构


### 四、quality_gate 数据模型

```python
# 后端返回 / metadata 存储
{
  "passed": false,
  "score": 72,
  "checked_at": "2026-07-07T12:00:00+08:00",
  "doc_type": "prd",
  "checks": [
    {
      "id": "prd.sections.mvp_table",
      "label": "MVP 功能为表格",
      "passed": true,
      "severity": "high",
      "detail": null
    },
    {
      "id": "prd.sections.scope",
      "label": "项目范围",
      "passed": false,
      "severity": "high",
      "detail": "缺少「不在范围内」内容"
    }
  ]
}
```

```typescript
export type QualityGateCheck = {
  id: string;
  label: string;
  passed: boolean;
  severity: 'high' | 'medium' | 'low';
  detail?: string | null;
};

export type QualityGateResult = {
  passed: boolean;
  score: number;
  checked_at: string;
  doc_type: 'prd' | 'api-docs' | 'prompts';
  checks: QualityGateCheck[];
};
```

**passed 规则：** 所有 `severity === 'high'` 的 check 均 passed 则 `passed: true`。

**score 规则：** `100 * passed_count / checks.length`，可加权（high 权重 2，medium 1）。

### 五、各文档类型检查项（首批）

#### PRD（`doc_type=prd`）

| id | 规则 |
|----|------|
| `prd.section.overview` | 含 `## 1. 产品概述` 或等价标题 |
| `prd.section.features` | 含 `## 2. 功能需求` |
| `prd.section.pages` | 含 `## 3. 页面设计` |
| `prd.section.tech` | 含 `## 4. 技术规格` |
| `prd.section.nfr` | 含 `## 5. 非功能需求` |
| `prd.section.scope` | 含 `## 6. 项目范围` |
| `prd.mvp.table` | MVP 区段含 Markdown 表格（`\| 功能名称 \|` 或 `\|功能名称\|`） |
| `prd.scope.in` | 「在范围内」下有非空内容 |
| `prd.scope.out` | 「不在范围内」下有非空内容 |
| `prd.pending.count` | 「待确认」出现次数 ≤5（超出为 medium warning） |

标题匹配允许 minor 变体（正则，不要求与 template 字节级一致）。

#### 接口文档（`doc_type=api-docs`）

| id | 规则 |
|----|------|
| `api.section.core` | 含「核心接口」类标题 |
| `api.section.edge` | 含「边缘接口」或「辅助接口」类标题 |
| `api.response.wrapper` | 含统一响应结构示例（`"code"` + `"data"` 或 team guidelines 关键词） |
| `api.path.prefix` | 含 `/api/v1` 或 PRD 声明的其他前缀 |
| `api.endpoint.count` | 识别 `###` / `####` + HTTP 方法 或路径行数 ≥1（启发式） |

#### 提示词（`doc_type=prompts`）

| id | 规则 |
|----|------|
| `prompts.section.context` | 含「项目总览」或「Project Context」 |
| `prompts.section.features` | 含「功能开发」 |
| `prompts.section.api` | 含「接口实现」或无 API 文档时 skip（见下） |
| `prompts.section.frontend` | 含「前端开发」 |
| `prompts.section.review` | 含「代码审查」或「Code Review」 |
| `prompts.feature.count` | 「功能开发」下 `###` 标题数 vs PRD MVP 行数，差值 ≤1（需传入 context） |

**prompts 的 MVP 对齐：** gate 调用时可传 `context: { prd_content?: str }`，从 PRD MVP 表格数行；无 PRD 则 skip 该 check 并记 `passed: true, detail: 'skipped'`。

**optimize Job：** 对优化后的正文同样跑 gate，覆盖 current metadata。

### 六、后端集成

#### `run_quality_gate(doc_type, content, context=None) -> dict`

- 纯函数，不访问 DB
- 内容为空：返回 single failed check `empty_content`

#### `job_runner._finalize_document_for_job`

在现有 `patch_current_metadata` / `build_metadata_from_job` 流程中：

```python
gate = run_quality_gate(doc_type, content, context=build_gate_context(job))
metadata = merge_metadata(existing, {
    "quality_gate": gate,
    "review": job.get("review"),  # 已有
})
```

`build_gate_context`：api-docs / prompts 可从 session 或 job payload 取 `prd_content` 片段（长度受限，仅用于 count 启发式）。

#### LLM 步骤 `llm_metrics`

可选新增 step 标签 `quality_gate`，**不调用 LLM**；仅日志记录耗时 <10ms。

### 七、PRD 流水线中的位置

保持现有 phase，在 `done` 事件前对 **最终正文** 跑 gate：

```
writer_started → ... → review_started → review
  → [rewrite_started → rewrite]（可选）
  → quality_gate（内存中，结果随 done 写入 metadata）
  → done
```

不在 SSE 中单独增加长阶段；若前端 Stepper 需要，可在 `done` 前发极短 phase `quality_check`（可选，**默认不发**，避免 Stepper 闪烁）。

### 八、前端 QualityReportPanel

**位置：** `DocumentReviewWithVersions` 内，`ReviewResultPanel` 下方或 Tab 切换（「审查意见 | 质量报告」）。

**展示：**

- 总分 + passed / 未通过 high 项计数
- checks 列表：通过灰勾，失败红叉 + detail
- 无 metadata 时（老数据）：不展示或「暂无质量报告」

**与 Review 的区别（UI 文案）：**

- Review：模型语义审查
- 质量报告：格式与结构规则检查

optimize 完成后 refresh 版本列表时应能看到更新后的 gate（沿用现有 job 完成 refresh 逻辑）。

### 九、错误与边界

- gate 抛错不应使 Job failed；catch 后写 `quality_gate: { passed: false, checks: [{ id: 'gate.error', ... }] }`
- 超大正文：只做 regex / 行扫描，不整篇 parse AST
- 老 session 无 gate：review 页正常，不报错

### 十、验收标准（本篇）

1. `quality_gate.py` 存在，对 sample PRD md 可跑通
2. PRD Job 完成后 `document_versions.metadata.quality_gate` 有值
3. 故意缺「项目范围」的 PRD 生成后 `passed: false`，UI 可见对应 check
4. api-docs、prompts Job 完成后同样有 gate metadata
5. PRD Rewrite 路径完成后 gate 针对 **最终稿** 而非 draft_v1
6. `pytest tests/test_quality_gate.py` ≥6 cases（prd/api/prompts 各 2）
7. `npm run build` 通过

### 十一、实现顺序建议

1. `quality_gate.py` + 单测（先用 `skills/.../examples` 里的 sample PRD）
2. 接入 `job_runner` finalize
3. `QualityReportPanel` + `DocumentReviewWithVersions`
4. 三产物各人工跑一条 Job 看报告
5. 调规则阈值（如「待确认」上限）根据抽测微调
