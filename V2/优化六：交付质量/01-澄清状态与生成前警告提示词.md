# 澄清状态与生成前警告提示词

点击此处可复制本篇提示词

本篇在澄清阶段引入 **澄清状态** 评估：顶栏展示对话是否收口；未澄清完成时仍允许生成 PRD，但按钮使用警告样式，点击时弹出二次确认并列出待确认问题。表单字段在进入澄清前已校验，澄清页不重复检查 `product_name`、`platform` 等。**交付守卫**（`canPerformAction` / `delivery_guards`）仅做极端兜底（如缺少摘要），与 03 篇 artifact 规则衔接。

## 使用场景

这份提示词用于 harnessprd 项目 `frontend/` 与 `backend/` 改造澄清页 UI 与生成 PRD 前的警告逻辑。

**前置条件**：结构化表单、`ClarificationStage`、`Summary Diff`、Generation Job 已可用。

**现状问题：** 澄清页无法直观反映「对话是否还有未回复问题」；用户可能在 AI 仍等待回复时直接生成 PRD。表单校验与澄清对齐状态混在一起，缺少分层约束。

**改造后的生成流程：**

```
messages 变更
  → assessClarificationState（启发式，无额外 LLM）
  → 顶栏 badge + 按钮警告样式
  → 用户点「生成 PRD」
  → needsConfirm ? confirm 列出 openQuestions : 直接进入 syncSummary
```

**本次不做：**

- 单独「评估完整度」按钮或额外 API 轮次
- 澄清未完成时 **硬禁止** 创建 PRD Job
- 澄清页底栏折叠式「待确认问题」面板（**仅顶栏状态 + 生成前 confirm**）
- 澄清状态在 Summary Diff 页、表单页展示
- 基线确认、quality_gate、下游 Review、交付包导出（见 02、03 篇）
- 改造 v1 `App.tsx`

### 一、功能目标

- `assessClarificationState(messages)`：基于澄清对话 **实时** 评估状态（纯启发式，零额外 LLM 等待）
- 澄清页 **顶栏**：状态 badge（如「澄清已收口 · 可生成 PRD」「澄清进行中 · 2 个待确认」）
- 「生成 PRD」**始终可点**（除 streaming / syncing / actionLocked），有警告时琥珀样式 + ⚠
- 点击生成且存在警告时，`confirm` 弹窗列出 `openQuestions` / `warnings`，用户确认后才进入 sync
- `canPerformAction` / `delivery_guards`：`generate_prd` 仅校验 **存在** `requirementsSummary`；澄清警告 **不** 导致 400

### 二、要解决的问题

澄清页需要回答两个问题：**对话里是否还有未收口的问题？若此时生成 PRD，用户是否已知情？**

- 表单阶段负责字段完整性与格式
- 澄清阶段负责对话对齐；约束方式为 **警告 + 确认放行**，而非禁用按钮
- 不在澄清页使用百分制评分或重复表单 blocker，避免与 AI 实际提问状态脱节

### 四、澄清状态数据模型

```typescript
export type ClarificationStatus = 'ready' | 'collecting' | 'awaiting_user_reply';

export type ClarificationState = {
  status: ClarificationStatus;
  openQuestions: string[];       // 从 AI 末条解析，供 confirm 展示
  warnings: string[];            // 如「尚未在对话中补充说明」
  statusLabel: string;           // 顶栏文案
  needsConfirmBeforeGenerate: boolean;
};
```

| status | 含义 |
|--------|------|
| `ready` | 末条 AI 无未决问题，或 AI 明确收口 |
| `awaiting_user_reply` | 最后一条可见消息是 AI，且含待回复问题 |
| `collecting` | 仍在收集信息（启发式） |

### 五、澄清状态规则

输入：`messages`（`getVisibleClarificationMessages`：跳过 system 与首条 seed）。

**从 AI 末条提取 `openQuestions`：**

- 编号列表且行末有 `?` / `？`
- 「需要澄清 / 待确认 / 请确认」段落后的编号项
- 去重，最多 5 条

**`needsConfirmBeforeGenerate`：**

- 末条为 AI 且 `openQuestions.length > 0`
- 或 `openQuestions.length > 0` 且 status 为 `collecting`
- 或 warnings 非空（如尚无 user 回复）

**`ready`：**

- 末条为 user，且当前无待展示 openQuestions；或
- 末条 AI 含收口语（「可以生成 PRD」「如果没有更多补充」「信息已经足够」）且无 openQuestions

计算随 `messages` 在 `useMemo` 中更新，<5ms。

**P1（可选）：** 澄清 `done` 事件附带 `clarification_meta` JSON，前端优先 structured，启发式兜底。

### 六、UI 行为

#### 顶栏（`ClarificationStage`）

```
澄清对话          澄清已收口 · 可生成 PRD              [返回表单] [生成 PRD]
澄清对话          澄清进行中 · 2 个待确认              [返回表单] [生成 PRD ⚠]
```

- 状态 badge 为 **只读展示**（非折叠面板入口）
- `needsConfirmBeforeGenerate`：主按钮使用警告样式（琥珀色 + ⚠），仍保持 enabled
- `isStreaming` / `isSyncingSummary` / `actionLocked` 时 disable

#### 底栏

- 保留 `ClarificationContextPanel`、`ClarificationWarnBanner`、`ChatInput`
- **不** 展示待确认问题折叠面板

#### 生成 PRD 流程

```
用户点「生成 PRD」
  → needsConfirmBeforeGenerate ?
       confirm 列出 openQuestions + warnings
       取消 → 中止
  → syncSummaryBackToForm → Summary Diff / Job
```

**不在表单页、Summary Diff 页展示澄清状态。**

### 七、交付守卫

#### 前端 `deliveryStage.ts`

```typescript
case 'generate_prd':
  if (!ctx.requirementsSummary) {
    return { allowed: false, reason: '缺少结构化需求摘要' };
  }
  return { allowed: true };
```

澄清 confirm 由 UI 处理，不写入 `allowed: false`。

#### 后端 `delivery_guards.py`

- `artifact == "prd"`：无 `requirements_summary` → 400
- 澄清未完成 **不** 400

### 十、错误与边界

- `messages` 为空：warnings「尚未开始澄清对话…」，confirm 一次后可生成
- `entryMode !== 'structured'`：无澄清页，本篇不适用
- 启发式误检：用户仍可通过 confirm 放行

---

### 十一、验收标准

1. 澄清页顶栏可见状态 badge，**无**底栏待确认折叠面板
2. AI 末条含编号问题时，顶栏「澄清进行中 · N 个待确认」；「生成 PRD ⚠」可点
3. 点击生成弹出 confirm；取消不进入 sync
4. 用户回复后（末条 user），无新 AI 提问时不强制 confirm
5. 后端 summary 存在即可创建 PRD Job；缺 summary 仍 400
6. `npm run build` 通过

```bash
cd frontend && npm run build
cd backend && pytest tests/test_delivery_quality.py -q
```
