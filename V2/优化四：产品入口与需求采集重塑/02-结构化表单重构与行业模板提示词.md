# 结构化表单重构与行业模板提示词

点击此处可复制本篇提示词

本篇把结构化需求表单从「管道符多行文本」升级为「可增删行的列表编辑器」，移除面向用户的 JSON 预览，并增加 2～3 个行业模板供一键填充。输出仍对齐 `RequirementsSummary` 与 `skills/prd-generator/references/field-schema.json`。

## 使用场景

这份提示词用于在 harnessprd 项目 `frontend/` 重构 AppV2 结构化表单的数据结构与 UI。

**前置条件**：表单页已能通过路径选择进入主路径（`formSubView === 'structured'`）。

**现状问题：** `mvp_features`、`ui_pages` 使用多行文本 + `｜` 分隔约定，用户需记忆格式；格式错误只能在提交校验时发现。JSON 预览面向开发者，对产品经理无实际帮助。

**改造后的数据流：**

```
StructuredFormData（行数组）
  → buildRequirementsSummary → RequirementsSummary
  → 澄清 / 生成 PRD

Session 加载
  → normalizeFormData（管道符字符串自动迁移为行数组）
```

**本次不做：**

- 改造路径选择页、导入向导
- 改造顶栏产出物进度条、PRD 审阅 CTA
- 修改后端 API 或 `field-schema.json`
- 澄清对话 Job 化
- 表单 JSON 反向编辑模式

### 一、功能目标

- `mvp_features`、`ui_pages` 改为 **行编辑器**（增删改），用户不再记忆 `｜` 格式
- 删除「查看 JSON 预览」按钮与预览面板；清理 `showJsonPreview` 状态及 Session 持久化
- `buildRequirementsSummary` / `summaryToFormData` / `validateStructuredForm` 适配新数据结构
- 老 Session 中管道符字符串 **自动迁移** 为行数组，加载时用户无需手动转换
- 新增 2～3 个行业模板 + 模板选择器（保留现有「朋友圈文案助手」示例）
- `npm run build` 通过

### 二、要解决的问题

当前表单用多行文本 + 管道符约定组织 MVP 功能与页面结构，例如：

```
场景分类选择｜提供 7 个预设场景标签｜降低思考成本
输入页｜场景分类,场景描述,生成按钮｜主输入视图
```

产品经理难以直接编辑该格式；格式错误只能在生成或校验阶段暴露。JSON 预览同样不适合作为常规录入界面。

改造后，用户在表格中填写「功能名称 / 描述 / 价值」「页面名 / 模块 / 备注」，系统在内部组装 `RequirementsSummary`。

### 四、数据结构

#### 新的 `StructuredFormData`（核心变更）

```typescript
export type MvpFeatureRow = {
  name: string;
  description: string;
  user_value: string;
};

export type UiPageRow = {
  name: string;
  modules: string;   // 单行文本，逗号分隔模块名，展示简单
  notes: string;
};

export type StructuredFormData = {
  product_name: string;
  product_goal: string;
  target_users: string;          // 仍用多行文本，每行一个用户群
  platform: string;
  mvp_features: MvpFeatureRow[]; // 改：由 string 改为数组
  v2_features: string;           // 仍用多行文本
  ui_pages: UiPageRow[];         // 改：由 string 改为数组
  interaction_notes: string;
  design_theme: string;
  responsive: string;
  auth: string;
  database: string;
  frontend: string;
  backend: string;
  deployment: string;
  llm_usage: string;
  security_requirements: string;
  performance_requirements: string;
  usability_requirements: string;
  in_scope: string;
  out_of_scope: string;
};
```

`DEFAULT_FORM`：`mvp_features: []`、`ui_pages: []`，至少留一行空行方便输入（或初始 `[{ name:'', description:'', user_value:'' }]`）。

#### `buildRequirementsSummary` 映射

```typescript
mvp_features: formData.mvp_features
  .filter((row) => row.name.trim() || row.description.trim())
  .map((row) => ({
    name: row.name.trim() || '待确认',
    description: row.description.trim() || row.name.trim() || '待确认',
    user_value: row.user_value.trim() || '待确认',
  })),
ui_pages: formData.ui_pages
  .filter((row) => row.name.trim())
  .map((row) => ({
    name: row.name.trim(),
    modules: row.modules.split(/[,，、]/).map((s) => s.trim()).filter(Boolean),
    notes: row.notes.trim(),
  })),
```

其余字段逻辑与现有实现一致（`parseList` 用于多行文本字段）。

### 五、老数据迁移

Session 里可能仍是旧格式（`mvp_features: string`）。在 `applySessionData` 或 `structuredFormTransform.normalizeFormData` 中处理：

```typescript
function normalizeFormData(raw: unknown): StructuredFormData {
  const base = { ...DEFAULT_FORM, ...(raw as Partial<StructuredFormData>) };
  if (typeof (raw as { mvp_features?: unknown })?.mvp_features === 'string') {
    base.mvp_features = legacyParseMvpFeatures((raw as { mvp_features: string }).mvp_features);
  }
  if (typeof (raw as { ui_pages?: unknown })?.ui_pages === 'string') {
    base.ui_pages = legacyParseUiPages((raw as { ui_pages: string }).ui_pages);
  }
  if (!Array.isArray(base.mvp_features)) base.mvp_features = [];
  if (!Array.isArray(base.ui_pages)) base.ui_pages = [];
  return base;
}
```

`legacyParseMvpFeatures` / `legacyParseUiPages` 复用现有 `AppV2` 中的 `parseMvpFeatures`、`parsePages` 逻辑，迁移完成后不再向用户暴露管道符格式。

### 六、行编辑器 UI 规格

#### `MvpFeatureRowEditor`

| 列 | 控件 | 必填 |
|----|------|------|
| 功能名称 | `TextInput` | 是（该行非空时） |
| 功能描述 | `TextInput` 或短 `TextArea` | 是 |
| 用户价值 | `TextInput` | 否 |

- 底部「+ 添加功能」
- 每行右侧「删除」；仅剩一行时删除 = 清空该行，不删到 0 行（避免无法输入）
- 移动端纵向堆叠，桌面端三列网格

#### `UiPageRowEditor`

| 列 | 控件 |
|----|------|
| 页面名称 | `TextInput` |
| 主要模块 | `TextInput`，placeholder「逗号分隔，如：登录表单, 验证码」 |
| 备注 | `TextInput` |

同样支持增删行。

#### 校验 `validateStructuredForm`

- `mvp_features`：过滤全空行后，至少 1 行且每行 `name`、`description` 非空
- `ui_pages`：过滤全空行后，至少 1 行且 `name` 非空
- 错误信息挂在表单级或第一行下方，例如「请至少填写一个 MVP 功能」

### 七、删除 JSON 预览

彻底移除：

- `showJsonPreview` state
- `requirementsPreview` useMemo
- 「查看 JSON 预览 / 隐藏 JSON 预览」按钮
- `requirements_summary 预览` 深色代码块区域
- `sessionService` 中 `showJsonPreview` 字段的读写

不要在 UI 留 `?debug=1` 开关（本阶段不需要）。

### 八、行业模板

在 `formTemplates.ts` 定义：

```typescript
export type FormTemplate = {
  id: string;
  label: string;
  description: string;
  data: StructuredFormData;
};
```

**至少包含以下 4 个（含原有示例）：**

| id | 名称 | 定位 |
|----|------|------|
| `friend-circle-copywriter` | 朋友圈文案助手 | 现有 `EXAMPLE_FORM` 迁移为新数组格式 |
| `internal-approval` | 内部审批流 | B 端：表单审批、权限、待办 |
| `content-community` | 内容社区 | C 端：发帖、评论、信息流 |
| `ai-copilot` | AI 助手 / Copilot | 对话式工具 + `llm_usage` 示例 |

每个模板需填齐主要区块（产品与用户、功能与页面、技术约束），MVP 不少于 4 行，页面不少于 2 行，便于演示列表编辑器。

#### `FormTemplatePicker`

- 放在结构化表单工具条（「填充示例」旁或替换之）
- 形式：下拉选择 + 「应用模板」按钮，或模板卡片横向滚动
- 应用前 `window.confirm`：「将覆盖当前表单内容，是否继续？」
- 应用后清空 `formErrors`
- 「填充示例」可合并进模板选择（默认选中朋友圈文案助手），避免两个入口做同一件事

### 九、`summaryToFormData`（澄清回填）

澄清后 `syncSummaryFromConversation` 可能更新 `requirementsSummary`，需写回表单：

```typescript
mvp_features: (summary.mvp_features || []).map((item) => ({
  name: item.name || '',
  description: item.description || '',
  user_value: item.user_value || '',
})),
ui_pages: (summary.ui_pages || []).map((item) => ({
  name: item.name || '',
  modules: (item.modules || []).join('，'),
  notes: item.notes || '',
})),
```

保证 Summary Diff 确认后表单与摘要一致。

### 十、`AppV2` 改造要点

1. `DEFAULT_FORM`、`EXAMPLE_FORM` 迁到 `formTemplates.ts` 或 `structuredFormTransform.ts`
2. 表单区 `mvp_features` / `ui_pages` 的 `TextArea` 换成行编辑器组件
3. `FieldLabel` 的 hint 去掉管道符说明，改为「点击添加行」类提示
4. `updateField` 扩展：支持 `updateMvpRow(index, patch)` 等，或行组件内部受控
5. `isExampleFilled` 逻辑：对比当前 form 与某模板 id，或保留简单标记

### 十一、验收标准

- 结构化表单中 **无** 管道符格式说明、**无** JSON 预览
- MVP、页面以列表形式增删编辑
- 校验：空 MVP、空页面名有明确错误提示
- 应用任一模版后表单填满，可正常开始澄清并生成 PRD
- 打开含旧管道符字符串的老 Session，表单正确显示为多行
- `summaryToFormData` 往返不丢字段
- `npm run build` 通过
