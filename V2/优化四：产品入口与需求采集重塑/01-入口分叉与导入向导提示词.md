# 入口分叉与导入向导提示词

点击此处可复制本篇提示词

本篇改造新建方案页的信息架构：由「三个 Tab 挤在同一页」改为「先选路径、再进入对应界面」。主路径进入结构化表单；导入路径进入独立的 PRD 或 PRD+接口文档粘贴向导。后端 `entryMode` 语义不变，仅调整前端路由与布局。

## 使用场景

这份提示词用于在 harnessprd 项目 `frontend/` 改造 AppV2 的方案入口与导入流程。

**前置条件**：`/v2`、`/v2/:id` 路由已存在；Session 保存与 `entryMode` 字段已可用。

**现状问题：** `viewState === 'form'` 时，顶部三个 Tab（从零开始 / 从 PRD 开始 / 从提示词开始）与下方整块内容绑定切换。结构化录入、PRD 粘贴、双文档粘贴混在同一页面，主路径用户每次都要经过非主路径 Tab，且与顶栏「流程进度」的线性语义不一致。

**改造后的页面流：**

```
/v2（无 session）
  → ProjectEntryChooser（路径选择）
  → structured | import-prd | import-prompts

已有 Session 加载
  → 按 entryMode 直接落到对应 formSubView，跳过 chooser
```

**本次不做：**

- 改造结构化表单字段（MVP 列表化、行业模板等）
- 改造顶栏产出物进度条与 PRD 审阅页按钮
- 改造澄清对话、生成 Job、RAG 门控
- 下线 v1 `App.tsx` 或修改 `/` 路由
- 澄清对话 Job 化或持久化增强
- 后端 API 变更

### 一、功能目标

- 新建方案时先展示 **路径选择页**（chooser），不再在表单顶栏用 Tab 切换三种入口
- **主路径**：「从零创建 PRD」→ 进入结构化表单（`entryMode = 'structured'`）
- **导入路径**：「导入已有素材」→ 二级选择：
  - 「我有 PRD」→ 粘贴 PRD 向导（`entryMode = 'prd'`）
  - 「我有 PRD + 接口文档」→ 双粘贴向导（`entryMode = 'prompts'`）
- 已有 Session 加载时，按 `entryMode` **直接落到对应界面**，不强制回到 chooser
- `SessionList` 入口标签文案与新区块一致
- 从 chooser 进入各子界面时，提供明确的「返回选择」入口
- `npm run build` 通过

### 二、要解决的问题

当前 `AppV2` 在 `viewState === 'form'` 时，顶部用三个 Tab 切换整块内容，存在以下问题：

1. **入口混杂**：「结构化需求录入」标题下同时放置完整表单与两个粘贴区，三种路径共用同一布局
2. **主次不清**：主路径（从零创建）用户每次进入表单页都要经过另外两个 Tab
3. **与顶栏进度语义冲突**：导入路径可跳过前置阶段，但表单区仍呈现为「同页三个选项」，与产出物进度不一致

改造后，用户先选择「从零创建」或「导入素材」，再进入对应专属界面。

### 三、代码结构

```
frontend/src/
  components/
    project-entry/
      ProjectEntryChooser.tsx       # 新建：路径选择卡片
      ImportPrdPanel.tsx            # 新建：导入 PRD 粘贴区 + 操作按钮
      ImportPromptsPanel.tsx        # 新建：导入 PRD + 接口文档粘贴区
  AppV2.tsx                         # 改造：form 区 orchestration
  components/SessionList.tsx        # 改造：入口标签文案
  services/sessionService.ts        # 类型不变；entryMode 继续持久化
```

**分层原则：**

| 层 | 职责 |
|----|------|
| `ProjectEntryChooser` | 两张路径卡片 + 导入二级入口 |
| `ImportPrdPanel` / `ImportPromptsPanel` | 粘贴 UI + 调 `AppV2` 传入的回调 |
| `AppV2` | 维护 `formSubView`、设 `entryMode`、调 `ensureSessionCreated`、切 `viewState` |

不要把导入面板的业务逻辑（`enterPrdReviewFromInput`、`startApiDocsFromPrdInput` 等）散落在三个新文件里重复实现——**面板只负责 UI，动作由 `AppV2` 以 props 传入**。

### 四、状态设计

在 `AppV2` 增加表单子视图状态：

```typescript
type FormSubView = 'chooser' | 'structured' | 'import-prd' | 'import-prompts';
```

**何时显示 chooser：**

| 条件 | 显示 |
|------|------|
| `viewState === 'form'` 且 `formSubView === 'chooser'` | 路径选择页 |
| 用户从子界面点「返回」 | chooser |
| `loadSession` 后已有 `entryMode` 且 `viewState !== 'form'` | 不显示 chooser（人在澄清或审阅） |
| `loadSession` 后 `viewState === 'form'` 且有 `entryMode` | 按 `entryMode` 映射到对应 `formSubView`，**跳过 chooser** |
| 全新 `/v2`（无 sessionId） | 默认 `formSubView = 'chooser'` |

**`entryMode` 与 `formSubView` 映射：**

| entryMode | formSubView |
|-----------|-------------|
| `structured` | `structured` |
| `prd` | `import-prd` |
| `prompts` | `import-prompts` |

用户在选择路径时同步 `setEntryMode(...)`，保证 Session 快照与列表页标签一致。

**Session 持久化：**

- 继续写入 `session_data.entryMode`
- 新增可选字段 `formSubView`（便于刷新后落在正确子页）；若未存，用 `entryMode` 推导即可

### 五、界面规格

#### 1. 路径选择页（`ProjectEntryChooser`）

布局：居中、两张主卡片 + 导入区折叠或次级卡片。

```
┌─────────────────────────────────────────────┐
│  新建 PRD 方案                               │
│  选择本次工作的起点                           │
├─────────────────────────────────────────────┤
│  ┌──────────────────┐  ┌──────────────────┐ │
│  │ 从零创建 PRD      │  │ 导入已有素材      │ │
│  │ 填写需求 → 澄清   │  │ 粘贴 PRD 或       │ │
│  │ → 生成全流程      │  │ PRD+接口文档      │ │
│  └──────────────────┘  └──────────────────┘ │
└─────────────────────────────────────────────┘
```

- **从零创建 PRD**：主按钮样式（深色底），点击 → `setEntryMode('structured')`、`setFormSubView('structured')`
- **导入已有素材**：次按钮或右侧卡片，展开/跳转到导入二级：
  - 「我有 PRD」→ `import-prd`
  - 「我有 PRD + 接口文档」→ `import-prompts`

文案面向产品用户，不使用 `entryMode`、`structured` 等内部字段名。

#### 2. 主路径区（`formSubView === 'structured'`）

- 保留现有表单区块与「开始澄清对话」按钮（字段改造不在本篇范围）
- 顶部增加面包屑或链接：**← 返回路径选择**
- 移除原来的三 Tab 切换条
- 移除「查看 JSON 预览」相关 UI（若仍存在，本篇直接删掉按钮与 `showJsonPreview` 切换入口；预览面板本体可在表单篇彻底清理）

工具条保留：填充示例、清空全部（行为不变）。

#### 3. 导入 PRD（`ImportPrdPanel`）

从现有 `entryMode === 'prd'` 区块抽出，交互不变：

| 控件 | 行为 |
|------|------|
| PRD 大文本框 | 绑定 `manualPrdInput` |
| 「进入 PRD 环节」 | 调 `onEnterPrdReview` → 现有 `enterPrdReviewFromInput` |
| 「直接生成接口文档」 | 调 `onStartApiDocs` → 现有 `startApiDocsFromPrdInput` |
| 「← 返回路径选择」 | `setFormSubView('chooser')` |

#### 4. 导入 PRD + 接口文档（`ImportPromptsPanel`）

从现有 `entryMode === 'prompts'` 区块抽出：

| 控件 | 行为 |
|------|------|
| PRD 文本框 | 必填 |
| 接口文档文本框 | 可选 |
| 「进入当前环节」 | 调 `onEnterStage` → 现有 `enterPromptsStageFromInput` |
| 「直接生成提示词」 | 调 `onStartPrompts` → 现有 `startPromptsFromInput` |
| 「← 返回路径选择」 | 回到 chooser |

### 六、`SessionList` 标签

更新 `ENTRY_MODE_LABELS`：

| entryMode | 新标签 |
|-----------|--------|
| `structured` | 从零创建 |
| `prd` | 导入 PRD |
| `prompts` | 导入 PRD+接口文档 |

列表页「阶段」字段逻辑不变。

### 七、`AppV2` 改造要点

1. 删除 `form` 区域内三 Tab 的 `role="tablist"` 代码块（约 1372–1401 行一带）
2. `viewState === 'form'` 时按 `formSubView` 分支渲染：
   - `chooser` → `ProjectEntryChooser`
   - `structured` → 原 structured 表单（无 Tab 包裹）
   - `import-prd` → `ImportPrdPanel`
   - `import-prompts` → `ImportPromptsPanel`
3. `resetPage()` 时 `formSubView` 重置为 `'chooser'`
4. `applySessionData`：根据 `entryMode` 设置 `formSubView`；若 session 含 `formSubView` 字段则优先使用
5. `buildSessionSnapshot` 写入 `formSubView`（可选）

**不要在本篇改动：**

- `stageItems` / 顶栏流程进度（留给产出物进度篇）
- `review-prd` 的 `actions` 数组
- `buildRequirementsSummary` / 表单字段类型

### 八、边界情况

| 场景 | 预期 |
|------|------|
| 澄清中点顶栏「结构化需求」 | 若 `entryMode === 'structured'`，回到 `formSubView = 'structured'`，不清空对话 |
| 导入路径审阅中点「返回入口」 | 回到 `import-prd` 或 `import-prompts`，不是 chooser（与现有 `goBackFromReviewPrd` 一致） |
| 老 Session 无 `formSubView` | 用 `entryMode` 推导子视图 |
| 在 chooser 未创建 session | 正常；首次点「进入 PRD 环节」等仍走 `ensureSessionCreated` |

### 九、验收标准

- 打开 `/v2`，首先看到路径选择页，**无**三 Tab
- 点「从零创建」进入表单，可返回 chooser
- 点「导入 PRD」进入粘贴页，两个按钮行为与改造前一致
- 点「导入 PRD+接口文档」进入双粘贴页，行为与改造前一致
- 老方案从列表进入，落在正确子界面，不丢 `entryMode`
- `SessionList` 入口标签为新文案
- 澄清、生成 PRD、接口文档、提示词主流程未被本篇改坏
- `npm run build` 通过
