# Generate Skill — 文档生成标准

## 核心目标

读完文章后，读者能真正学到并理解这个知识点——不是看过，是学到。

---

## 风格要求

- 语言自然流畅，像一个懂行的人在认真讲解，而不是在堆砌信息
- 表现形式可以多样：叙述、举例、对比、反问、代码示例……根据内容选择最合适的方式，不必拘泥于固定结构
- 段落之间衔接自然，上下文有逻辑呼应，不能读起来像一段一段孤立的条目
- 不要出现翻译腔式的中文表述

## 格式要求

**1. 严格控制双引号使用频率，避免滥用**
  - 双引号只用于引用他人原话。其他所有情况一律不加双引号，包括：术语、对比短语、概括性描述、口语化表达、强调词组。需要强调时改用加粗。
  - 自造的概括性短语也不加引号，即使是作者自己提炼的对比词组或总结性说法，也不得用引号框定，需要强调时改用加粗。 


**2.禁止使用双破折号夹注结构（即"——补充说明——"夹在主干中间）**

需要补充信息时，优先拆分为两句，或重组语序，让补充内容自然落在句末/句首；只在单处使用破折号时允许用作转折或引出。

**3. 禁止在括号里放举例内容**

需要举例时，用"比如""例如""包括"引出，作为句子的自然组成部分；或者直接把例子写进主句，用顿号并列。括号只用于真正的补充说明（如单位换算、缩写解释），不用于举例。

**4. 控制破折号使用频率**

全篇破折号不超过 3 处。每次使用前先问：这里能不能拆成两句？能拆且拆了更自然，就拆，不用破折号。破折号只在真正需要转折停顿或引出补充、且拆句会损失语气时才用。

**5. 通用教程中工具专有名词须有说明**

在非特定工具的通用教程里，首次提到工具专有配置文件（如 CLAUDE.md、.cursorrules）时，须说明所属工具，并声明后文统一用该名称指代同类配置。专门介绍某个工具的章节无需此说明。

**6. 控制单句长度**

单句不超过 20 字，含英文时不超过 25 字。超过则拆成两句。

**7. 首次介绍知名框架、组件库、平台或工具时附官网地址**                              

在专门介绍某个框架、组件库、平台或工具的段落末尾，附上其官网链接。链接文本使用域名本身，格式为官网：[domain.com](https://domain.com)。         
                 
仅在首次介绍时附一次，正文中其他提及处不重复。

## 可用的表现形式

文章不必全程文字叙述，根据你的判断，在合适的场景下考虑使用以下形式：

### 表格

适合呈现对比关系、多维度属性、横向比较。例如对比 AI 替代前后的工作方式：

| | 替代前 | 替代后 |
|---|---|---|
| 产品经理 | 写 PRD | 审 PRD |
| 设计师 | 手动切图标注 | 确认工具输出 |


### 代码块

适合展示具体示例、配置、命令。必须标注语言类型，避免裸代码块：

```python
# 示例：AI 辅助生成用例
def generate_test_cases(feature_desc: str) -> list:
    ...
```

### 文本原型图

适合在无需截图的情况下示意界面结构或交互布局，用 ASCII 字符表达即可：

```
┌─────────────────────────────┐
│  页面标题                    │
├─────────────────────────────┤
│  [搜索框]          [筛选 ▼] │
│                             │
│  ● 列表项 A        >        │
│  ● 列表项 B        >        │
│  ● 列表项 C        >        │
└─────────────────────────────┘
```

### 引用块

适合强调关键结论、引用观点或做补充说明：

> AI 替代的不是判断，是判断之后的执行。

### 加粗与行内代码

- **加粗**用于强调核心观点，不要每段都用，用滥了就没有重点
- `行内代码` 用于提及具体的技术名词、字段名、命令

---

## 硬性要求

- **不使用分割线**（`---` 或 `***`）
- **不使用"精炼回答""扩展分析"等固定标签**作为段落标题
- **不使用Mermaid 流程图**
- 不在文章开头写结论性总结段，让内容自己说话
- 标题层级不跳级，`##` 之下才能用 `###`
- 代码块必须成对出现，并标注语言类型
- 文章的一级标题下不要直接出现第一个二级标题（`##`）
