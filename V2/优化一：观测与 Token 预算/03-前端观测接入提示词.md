# 前端观测接入提示词

点击此处可复制本篇提示词

前端观测接入的目标，是把后端已有的 **`run_summary`** 和 **`context_usage`** 转为可展示的 UI 反馈：

- **生成中：** 当前在第几步、已等待多久（不是假进度条）
- **生成完：** 折叠统计（耗时、约多少 tokens、请求 ID 可复制）
- **澄清上下文接近上限时：** 展示自然语言告警条，不直接暴露 context window 等专业术语

**实现原则：** 观测相关逻辑从 `AppV2.tsx` 抽离到 utils / hook / 小组件；`AppV2` 只负责 orchestration（何时调 API、切 viewState），**不要**把步骤映射、timer、错误格式化全堆在页面里。

## 使用场景

这份提示词用于在 harnessprd 项目 `frontend/` 接入观测数据。

**前置条件**：01 已完成（SSE 有 `run_summary`，error 含 `request_id`）。02 可选（无 02 时无 `context_usage`，澄清 warn 条不展示即可）。

后端在流程结束时发送 `run_summary`；澄清的 **`start-stream` 与 `continue-stream`** 的 `done` 均可带 `context_usage`。若项目已 Job 化，Job SSE 流同样在结束时发 `run_summary`，解析方式类似。

**展示原则（给用户看什么 / 不看什么）：**

| 给用户 | 不给用户 |
|--------|----------|
| 当前在第几步 | token 百分比进度条 |
| 已等待多久 | 逐步 token 实时跳动 |
| 完成后：耗时、约总 tokens | context window 等专业术语 |
| 失败：复制 request_id | 原始日志链接 |

### 一、功能目标

- 扩展 `services/api.ts` 的 `readStream`：解析 `run_summary`、`context_usage`
- 新增 `utils/generationSteps.ts`：步骤定义与 phase / run_summary 映射（纯函数，无 React 依赖）
- 新增 `utils/streamErrors.ts`：`StreamError` 友好文案与 `request_id` 提取
- 新增 `hooks/useGenerationObservability.ts`：观测 state + timer + SSE handler 工厂
- 新增 `GenerationStepper.tsx`、`RunSummaryPanel.tsx`：生成中 / 完成后 UI
- 新增 `StreamErrorBanner.tsx`、`ClarificationWarnBanner.tsx`、`ClarificationContextPanel.tsx`
- 改造 `DocumentReview.tsx`：嵌入 Stepper 与 RunSummary
- 改造 `AppV2.tsx`：各生成流程调用 hook，页面层保持薄

**本次不抽：** 表单解析、session、summary diff、完整 `generate*` 业务流程。只抽优化一观测 UI 相关块。

**分层职责：**

| 层 | 职责 |
|----|--------------|
| `utils/generationSteps` | 步骤条长什么样；后端 phase 怎么映射成 UI 状态 |
| `utils/streamErrors` | 识别 Token 超限；失败文案格式化 |
| `hooks/useGenerationObservability` | 观测 state、计时器、SSE 回调工厂 |
| `components/*` | 纯展示，无业务逻辑 |
| `AppV2` | 何时 begin/stop、切页面、调 API |

### 三、TypeScript 类型

在 `types/index.ts` 增加（字段名与后端一致，消费处按 optional 处理，后端未上线时不 crash）：

```typescript
export type RunStepSummary = {
  step: string;              // 步骤名，如 prd_writer
  input_tokens?: number;
  output_tokens?: number;
  duration_ms?: number;
};

export type RunSummary = {
  request_id: string;          // 请求 ID，失败时可复制
  run_type: string;            // 流程类型
  total_duration_ms: number;   // 总耗时
  total_input_tokens: number;
  total_output_tokens: number;
  llm_call_count: number;      // 调了几次模型
  revision_applied?: boolean;  // PRD 是否自动改过一轮
  steps?: RunStepSummary[];
  budget?: {                  // 02 可选：预算检查结果
    estimated_input_tokens: number;
    budget_tokens: number;
    ratio: number;
    level: string;
  };
};

export type ContextUsage = {
  estimated_input_tokens: number;  // 估算 input 长度
  budget_tokens: number;           // 有效上限
  ratio: number;
  level: 'ok' | 'warn' | 'exceed'; // 前端主要看 level 决定是否 amber
  // 以下可选，02 扩展；前端不展示，按 optional 忽略
  budget_source?: 'policy' | 'hardware';
  model?: string;
  policy_cap?: number;
  hardware_cap?: number;
};
```

### 四、readStream 扩展

在 `api.ts` 增加 `StreamError`（含 `code`、`request_id`），并在现有 handlers 上**扩展**，保留 `onPhase`、`onReview`：

```typescript
export type StreamHandlers = {
  onPhase?: (phase: string) => void;
  onReview?: (review: PrdReviewResult) => void;
  onRunSummary?: (summary: RunSummary) => void;
  onContextUsage?: (usage: ContextUsage) => void;
};
```

**解析逻辑：**

- `event.type === 'run_summary'` → 去掉 `type` 后调用 `onRunSummary`
- `event.type === 'done'` 且带 `event.context_usage` → 调用 `onContextUsage`
- `event.type === 'error'` 且 `event.code === 'TOKEN_BUDGET_EXCEEDED'` → `throw new StreamError(...)`
- `event.type === 'error'` 且含 `request_id` → 保留供 UI 复制

需在以下 API 支持 handlers：`generatePrdStream`、`generatePrdFromSummaryStream`、`generateApiDocsStream`、`generatePromptsStream`、`optimizeDocumentStream`；**`startConversationStream` 与 `continueConversationStream`** 均需 `onContextUsage`。若已 Job 化，`jobStream.ts` 同样解析 `run_summary`。

### 五、utils/generationSteps.ts

纯函数，无 React 依赖。`StepItem` 可在此定义后 re-export，或从 `GenerationStepper` 导出。

**步骤定义（用户看到的文案）：**

```typescript
export const PRD_STEP_DEFS = [
  { id: 'writer', label: '起草 PRD' },
  { id: 'review', label: '机器审查' },
  { id: 'rewrite', label: '修订 PRD' },
];

export const API_DOCS_STEP_DEFS = [
  { id: 'generate', label: '生成接口文档' },
  { id: 'review', label: '机器审查' },
];

export const PROMPTS_STEP_DEFS = [
  { id: 'generate', label: '生成提示词套件' },
  { id: 'review', label: '机器审查' },
];

export const REVIEW_STEP_HINT =
  '正在对照需求审查文档，通常需要 10–30 秒…';
```

**映射函数：**

| 函数 | 用途 |
|------|------|
| `mapPrdPhaseToSteps(phase)` | 后端 phase → StepItem[] |
| `finalizePrdStepsFromSummary(summary)` | 收到 run_summary 后，按 `revision_applied` 收束三步 |
| `createApiDocsGeneratingSteps()` | 接口文档：第 1 步 active |
| `markApiDocsReviewSteps()` | 审查中：第 1 步 done，第 2 步 active |
| `markApiDocsStepsDone()` | 两步均 done |
| `createPromptsGeneratingSteps()` / `markPromptsStepDone()` | 提示词两步 |
| `getPrdFailureStageLabel(stage)` | 失败文案：「机器审查」等 |

**PRD phase 与 Stepper 对应：**

| 后端 phase / 条件 | Stepper 表现 |
|-------------------|--------------|
| `writer_started` | 第 1 步 active（起草中） |
| `review_started` | 第 1 步 done，第 2 步 active + hint |
| `rewrite_started` | 第 2 步 done，第 3 步 active |
| `run_summary` + `revision_applied=false` | 前两步 done，第 3 步 pending（跳过改写） |
| `run_summary` + `revision_applied=true` | 三步均 done |

收到 `run_summary` 时必须调 `finalizePrdStepsFromSummary`：审查通过时没有 `rewrite_started`，**不能单靠 phase 判断**第三步是否跳过。

### 六、utils/streamErrors.ts

```typescript
import { StreamError } from '../services/api';

export function getErrorMessage(error: unknown, fallback: string): string;
export function getErrorRequestId(error: unknown): string | null;
export function formatPrdGenerationFailure(
  stage: PrdGenerationStage,
  elapsedSeconds: number,
  error: unknown,
): string;
```

- **`TOKEN_BUDGET_EXCEEDED`：** 直接返回后端 `message`（已是友好中文），不加 fallback 前缀
- **其他 SSE error：** `{fallback}：{message}`
- **`formatPrdGenerationFailure`：** 生成在「{阶段}」阶段失败 · 已等待 {n}s

### 七、hooks/useGenerationObservability.ts

统一管理观测 state 与 timer，避免 `AppV2` 内散落 `useState` / `setInterval`。

**内部 state：**

```typescript
runSummary: RunSummary | null
contextUsage: ContextUsage | null
generationSteps: StepItem[]
generationElapsed: number          // 已等待秒数
generationHint: string | undefined // 如 Review 阶段的说明
errorRequestId: string | null
```

**对外 API（示例）：**

```typescript
const obs = useGenerationObservability();

// 读
obs.runSummary
obs.contextUsage
obs.generationSteps
obs.generationElapsed
obs.generationHint
obs.errorRequestId

// 流程控制
obs.resetGeneration()           // 新一轮：清 summary、steps、hint
obs.resetErrorMeta()
obs.startTimer() / obs.stopTimer()
obs.clearSteps()

obs.beginApiDocsGeneration()
obs.beginPromptsGeneration()
obs.beginPrdGeneration()

obs.handleContextUsage(usage)
obs.handleRunSummary(summary, { finalizeSteps? })

obs.captureStreamError(error): { message: string; requestId: string | null }
obs.copyErrorRequestId()

// SSE handler 工厂（返回 StreamHandlers 片段，传给 api.readStream）
obs.createApiDocsHandlers()
obs.createPromptsHandlers()
obs.createPrdHandlers({ onPhase, onReview, getStageRef })
```

**原则：**

- hook 管「观测状态怎么变」
- `AppV2` 管「调 API 后切哪个 viewState」
- `prdGenerationStage` 仍留 `AppV2`；失败文案通过 `getStageRef` 或 callback 传入 hook

### 八、GenerationStepper 组件

**Props：**

```typescript
type StepItem = {
  id: string;
  label: string;
  status: 'pending' | 'active' | 'done';
};

type GenerationStepperProps = {
  steps: StepItem[];
  elapsedSeconds: number;
  hint?: string;
};
```

**UI 示例：**

```text
● 起草 PRD  →  ○ 机器审查  →  ○ 修订 PRD          已等待 27s
```

- `active`：高亮 + spinner
- `done`：✓
- `pending`：灰色 ○
- `已等待 {n}s`：hook 内 timer 驱动，生成结束 `stopTimer`

Review 阶段 hint 文案见 `REVIEW_STEP_HINT`（说明当前处于审查阶段，避免用户误判为无响应）。

### 九、RunSummaryPanel 组件

**Props：** `summary: RunSummary | null`、`defaultCollapsed?: boolean`

折叠行示例：

```text
▸ 本次生成：47s · 约 34k tokens
```

展开含：总耗时、约 tokens（输入/输出）、LLM 调用次数、是否自动修订、request_id + 复制按钮。

`formatTokens(n)`：`n >= 1000` 时显示「约 Xk」。可放在组件同文件 export。

展示位置：`DocumentReview` 底部，Review Agent 结果卡片下方；`review-prd` 页保留最后一次 summary。

### 十、StreamErrorBanner / ClarificationWarnBanner

**StreamErrorBanner** — 替换 `AppV2` 内联 error 区块：

```typescript
type StreamErrorBannerProps = {
  message: string;
  requestId?: string | null;
  onCopyRequestId?: () => void;
};
```

**ClarificationWarnBanner** — 澄清输入框上方，当 `contextUsage.level` 为 **`warn` 或 `exceed`** 时渲染：

```text
已讨论较多内容。若无更多补充，可以结束澄清并生成 PRD。
```

**ClarificationContextPanel** — warn 条之上，折叠展示**每轮**澄清的 context 统计：

```text
▸ 澄清 context：3 轮 · 最新约 2.1k / 60k
```

展开后每行：`首轮` / `第 N 轮` · 输入约 X / Y tokens · 耗时 · 状态（正常/偏多/超限）。数据来自每轮 SSE `done.context_usage` + `run_summary`，前端按轮累积。

**不要**显示 ratio 百分比；**不要**展示 `budget_source` 等调试字段。

### 十一、DocumentReview 改造

```typescript

generationElapsed?: number;
generationHint?: string;
runSummary?: RunSummary | null;
```

标题栏下插入 `<GenerationStepper />`；Review 结果卡片下方插入 `<RunSummaryPanel />`。

### 十二、AppV2 接入（薄层）

`AppV2` 顶部：

```typescript
const obs = useGenerationObservability();
```

各 generate 函数模式：

```typescript
obs.resetGeneration();
obs.resetErrorMeta();
obs.beginPrdGeneration();
obs.startTimer();

try {
  await conversationApi.generatePrdFromSummaryStream(..., {
    ...obs.createPrdHandlers({ onPhase, onReview, getStageRef: () => prdGenerationStageRef.current }),
  });
  setViewState('review-prd');
} catch (err) {
  setError(obs.captureStreamError(err, { kind: 'prd', stageRef: prdGenerationStageRef }).message);
  obs.clearSteps();
  obs.stopTimer();
}
```

**接入点：**

| AppV2 中的函数 | hook 方法 |
|----------------|-----------|
| `startConversation`（澄清首轮） | `handleContextUsage`；`captureStreamError` |
| `continueConversation` | `handleContextUsage`；`captureStreamError` |
| `generateApiDocs` | `beginApiDocsGeneration` + `createApiDocsHandlers` |
| `generatePrompts` | `beginPromptsGeneration` + `createPromptsHandlers` |
| `generatePrdForSummary` | `beginPrdGeneration` + `createPrdHandlers` |

澄清区：

```tsx
<ClarificationContextPanel rounds={obs.clarificationRounds} />
<ClarificationWarnBanner visible={obs.contextUsage?.level === 'warn' || obs.contextUsage?.level === 'exceed'} />
```

澄清流式 handler 使用 `obs.createClarificationHandlers()`（累积每轮 `context_usage` + `run_summary`）。  
全局 error：`<StreamErrorBanner message={error} requestId={obs.errorRequestId} onCopy={obs.copyErrorRequestId} />`

**budget reject：** error 区展示后端 `message`；可禁用继续发送或只保留「生成 PRD」。

**生成失败（含 request_id）示例：**

```text
生成在「机器审查」阶段失败 · 已等待 23s · [复制请求 ID]
```

### 十三、实施顺序

1. `types/index.ts` + `api.ts`（readStream、`StreamError`）
2. `utils/generationSteps.ts` + `utils/streamErrors.ts`
3. `GenerationStepper.tsx` + `RunSummaryPanel.tsx`
4. `hooks/useGenerationObservability.ts`
5. `StreamErrorBanner.tsx` + `ClarificationWarnBanner.tsx` + `ClarificationContextPanel.tsx`
6. `DocumentReview.tsx` 改造
7. `AppV2.tsx` 接入（建议先 prompts / api-docs，再 PRD / continue）
8. `npm run build` 回归

每步保持行为不变，避免一次大改。

### 十四、验收标准

- 生成 PRD 时可见三阶段 Stepper，Review 阶段已用时仍递增，**无**百分比进度条
- Writer / Rewrite 正文流式输出；Review 阶段有 hint 或第二步高亮，避免白屏无反馈
- 完成后折叠统计可展开，request_id 可复制
- 接口文档 Stepper 为「生成接口文档 → 机器审查」；提示词为「生成 → 审查」两步
- 澄清每轮结束后折叠面板可展开，看到各轮输入约 X / cap tokens
- `context_usage.level` 为 `warn` 或 `exceed` 时出现澄清 amber 提示
- 澄清首轮（`start-stream`）结束后，若后端返回 `context_usage`，前端应能展示 amber 提示
- `TOKEN_BUDGET_EXCEEDED` 时展示友好中文，非原始 API 错误
- 后端未发 `run_summary` 时页面不 crash（字段 optional）
- 收到 `run_summary` 后 Stepper 与 `revision_applied` 一致；现有 `onPhase` / `onReview` 行为不受影响
- 观测逻辑位于 utils / hook / 组件，`AppV2` 无大段步骤映射与 timer 代码
