# 观测与 Token 预算测试验收

## 测试准备

观测、Token 预算（含模型注册表 + 双层 budget）、前端接入相关代码已完成。

环境要求：

- `backend/.env` 配好 LLM（如 DeepSeek：`OPENAI_API_KEY` + `OPENAI_BASE_URL` + `DEFAULT_LLM_MODEL=deepseek-v4-flash`）
- `backend/config/models.yaml` 含 `deepseek-v4-flash` 与 `default` 条目
- 后端 `uvicorn main:app --reload` 已启动
- 前端 `npm run dev` 已启动，能打开 `/v2` 结构化流程
- `LOG_LLM_METRICS=true`（便于看 JSON 日志）

**澄清 warn 测试推荐配置**（业务 cap，不是模型窗口）：

```env
TOKEN_BUDGET_MODE=warn
CHAT_HISTORY_BUDGET=60000
```

有效 budget 为 **60000**（业务 cap；DeepSeek 下物理 input 顶约 62 万，policy 生效）。ratio ≥ 0.6（约 3.6 万 token input）应出现 warn。**不要用**极小的 `CHAT_HISTORY_BUDGET`（如 5000）测 warn——分母过小会导致行为异常。

测试 reject 模式时，可临时覆盖：

```env
CHAT_HISTORY_BUDGET=8000
TOKEN_BUDGET_MODE=reject
```

构造超长 messages continue。测完改回正常值。

## 一、观测链路测试

### 1. request_id 贯穿响应

```bash
curl -s -D - -X POST http://127.0.0.1:8000/api/conversation/start-stream \
  -H "Content-Type: application/json" \
  -d '{"initial_input":"测试产品","form_data":{}}' \
  -o /dev/null | grep -i x-request-id
```

预期：响应头含 `X-Request-ID: req_...`。

### 2. PRD 生成 SSE 含 run_summary

用示例表单走 structured 流程，或 curl 调 `generate-prd-from-summary-stream`。

预期 SSE 事件顺序大致为：

1. `phase: writer_started`
2. 若干 `text_delta`
3. `phase: review_started`
4. `review`
5. 可能 `phase: rewrite_started` + `text_delta`
6. `type: run_summary`（含 `request_id`、`steps`、`total_input_tokens`）
7. `data: [DONE]`

`run_summary.steps` 至少含 `prd_writer`、`prd_review`；若修订则含 `prd_rewrite`。

### 3. 日志可按 request_id 串联

从 run_summary 复制 `request_id`：

```bash
grep 'req_xxxxxxxx' | grep llm_step
```

预期：同一 request_id 下多条 JSON，`step` 与 SSE phase 对应；`duration_ms` 有值。

### 4. 能对比各 step 的 token 与耗时

对比同一次 run 各 step 的 `input_tokens` 和 `duration_ms`。

预期：能明确说出哪一步 input 最大、哪一步最慢。

## 二、前端展示测试

### 1. PRD 生成 Stepper + 已用时

1. 打开 `/v2`，填示例表单，走澄清 → 生成 PRD
2. 观察 `generating-prd` 页面

预期：

1. 三步 Stepper：起草 → 机器审查 → 修订（修订可能跳过）
2. 「已等待 Ns」每秒递增
3. Writer / Rewrite 正文流式增长
4. Review 阶段有 hint 或第二步高亮，不像白屏卡死
5. 无百分比进度条

### 2. 完成后折叠统计

进入 `review-prd` 页。

预期：

1. 底部「▸ 本次生成：Xs · 约 Xk tokens」
2. 展开可见 request_id，复制可用
3. Review Agent 结果卡片正常

### 3. 接口文档与提示词

分别生成接口文档、提示词。

预期：

1. 接口文档：检索规范 → 生成文档
2. 提示词：单步 + 已用时
3. 均有 run_summary 折叠区

### 4. 澄清 warn 提示

使用推荐配置 `CHAT_HISTORY_BUDGET=60000`，走结构化澄清并多聊若干轮；或填完表单等**首轮 AI 回复结束**（`start-stream` 的 `done` 也可能带 `context_usage`）。

预期：

1. `level=warn` 或 `exceed` 时输入框上方 amber 提示
2. 无 ratio 数字、无进度条
3. 短对话（少量轮次、总 token 远低于 cap）不出现

## 三、Token 预算测试

### 1. 模型注册表

1. 确认 `config/models.yaml` 存在且含 `deepseek-v4-flash`、`default`
2. `.env` 中 `DEFAULT_LLM_MODEL=deepseek-v4-flash`（或 `deepseek-chat` 别名）
3. 发起一次 `continue-stream`，看 `done.context_usage` 或日志

预期：

1. 澄清场景 `budget_tokens` 为 **60000**（业务 cap），不是 1000000（模型物理顶）
2. 临时改为未登记模型名，应 fallback 到 `default` 窗口，日志有 unknown model warn

### 2. warn 模式不阻断

```env
TOKEN_BUDGET_MODE=warn
CHAT_HISTORY_BUDGET=60000
```

正常澄清若干轮，直至 ratio 进入 warn。

预期：

1. `start-stream` / `continue-stream` 的 `done` 含 `context_usage`
2. warn 时日志有 `token_budget_warn`，对话仍可继续
3. 第六轮仅约 1 万 token 时**不应** warn（除非 cap 极小）

### 3. reject 模式阻断

```env
TOKEN_BUDGET_MODE=reject
CHAT_HISTORY_BUDGET=8000
```

构造较长 messages continue。

预期：

1. SSE `type: error`，`code: TOKEN_BUDGET_EXCEEDED`
2. 有明确中文 `message`
3. 该请求无 `llm_step` 日志
4. 前端 error 区展示友好文案

### 4. sync-summary 超长 reject

对 `sync-summary-from-conversation` POST 超大 `conversation_messages`。

预期：HTTP 422，可读错误信息。

## 五、失败排查

| 现象 | 可能原因 | 查什么 |
|------|----------|--------|
| 无 run_summary | finish 未 emit | conversation.py SSE generator |
| steps 缺 review | step 未替换 | prd_review_agent.py |
| 前端无 Stepper | onPhase 未接 | AppV2 generatePrdForSummary |
| token 全为 0 | usage_metadata 未读 | llm_factory wrapper |
| reject 不生效 | MODE 或 budget | .env + check_budget |
| 澄清从不 warn | cap 太大或只对齐 1M | `CHAT_HISTORY_BUDGET`、models.yaml、`budget_tokens` 是否为 policy 值 |
| cap 很小仍无 warn | 未接 start-stream | `start-stream` done 是否含 context_usage；前端 `onContextUsage` |
| cap=5000 行为怪异 | CHAT_HISTORY_BUDGET 过小 | 澄清 cap 建议 ≥ 60000 |
| Review 像卡死 | hint 未做 | GenerationStepper |
| 未知模型无 fallback | yaml 未加载 | model_registry.py、default 条目 |
