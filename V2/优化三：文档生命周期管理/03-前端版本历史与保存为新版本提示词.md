# 前端版本历史与保存为新版本提示词

点击此处可复制本篇提示词

前端版本 UI 的目标，是在 `review-*` 页增加版本历史侧栏与「保存为新版本」按钮：默认展示 current 工作稿；点击历史版本进入只读预览；预览时可「恢复此版本」，以该历史正文创建下一版并设为 current，已有历史行不删不改。手改仍走现有 debounce 自动保存，不新增「保存」「定稿」按钮。

**实现原则：** 版本相关逻辑不进 `AppV2.tsx`。HTTP 放 `documentApi.ts`，状态放 `hooks/useDocumentVersions.ts`，侧栏放 `components/DocumentVersionPanel.tsx`；版本与 `DocumentReview` 的接线收进 `components/DocumentReviewWithVersions.tsx`。`AppV2` 在三个 `review-*` 页只渲染该组件，传入 `sessionId`、`docType`、正文与原有 props，不直接调 `useDocumentVersions`。

## 使用场景

这份提示词用于在 harnessprd 项目 `frontend/` 接入文档版本 UI。

**前置条件**：

- 后端 Document API（含 restore、note 接口）可用
- `POST /api/session/save` 已能同步 current 版本
- Job 完成会写 current 版本与 Session 镜像

**展示原则：**

| 展示 | 不展示 |
|------|--------|
| 版本号、来源标签（生成/优化/另存等）、时间 | `content_preview` 自动摘要 |
| 用户填写的版本备注 | token 统计进度条 |
| 当前稿 / 预览稿正文 | 定稿、diff、审核工作流 |
| PRD 生成时的 review（附免责声明） | 优化后刷新的 review |

**本次不做：**

- 改造 v1 `App.tsx`
- 两版 diff
- 定稿与审核 UI
- 改造澄清对话与生成 Job 主流程
- `DocumentStageView` 等进一步合并 generating / review 六段 JSX

### 一、功能目标

- 新建 `services/documentApi.ts`：6 个 API 封装（含 restore、版本备注）
- 新建 `hooks/useDocumentVersions.ts`：拉列表、预览、checkpoint、restore、保存备注
- 新建 `components/DocumentVersionPanel.tsx`：侧栏、「保存为新版本」、每版「备注」
- 新建 **`components/DocumentReviewWithVersions.tsx`**：组合 hook、侧栏与 `DocumentReview`
- 轻改 `DocumentReview.tsx`：支持版本侧栏布局与预览态 props
- 薄改 `AppV2.tsx`：`review-*` 用 `DocumentReviewWithVersions` 替换直接使用的 `DocumentReview`
- `npm run build` 通过

### 五、`useDocumentVersions`

```typescript
type UseDocumentVersionsArgs = {
  sessionId: string | undefined;
  docType: DocumentType;
  editorContent: string;
  enabled: boolean;
};

type UseDocumentVersionsReturn = {
  versions: DocumentVersionListItem[];
  currentVersionNo: number | null;
  preview: DocumentVersionDetail | null;
  previewVersionId: string | null;
  isLoadingList: boolean;
  isLoadingPreview: boolean;
  isCheckpointing: boolean;
  isRestoring: boolean;
  savingNoteVersionId: string | null;
  error: string | null;
  refreshList: () => Promise<void>;
  openPreview: (versionId: string) => Promise<void>;
  closePreview: () => void;
  checkpoint: () => Promise<void>;
  restorePreview: () => Promise<string | null>;
  saveVersionNote: (versionId: string, changeNote: string) => Promise<void>;
};
```

`enabled` 为 true 且 `sessionId` 存在时，mount 调 `fetchVersionList`。

**行为约定：**

1. `openPreview(id)`：若 id 为 current，则 `closePreview` 回到编辑态；否则拉详情，编辑区只读展示 `preview.content`
2. `checkpoint`：`POST checkpoint`，body 为 `{ content: editorContent }`；**不传 `change_note`**；成功后 `refreshList`、`closePreview`
3. `restorePreview`：`POST .../versions/{id}/restore`；成功后 `onContentChange(content)`、`refreshList`、`closePreview`
4. `saveVersionNote`：`PATCH .../versions/{id}/note`；成功后就地更新列表项 `change_note`，不 `refreshList` 全表亦可
5. 不在 hook 内监听 Job；由 `DocumentReviewWithVersions` 在 Job 空闲后调 `refreshList`

**预览模式与编辑：**

- `preview` 非空时，textarea 只读，顶栏提示：「正在预览 v{n}，恢复后将基于该版本创建新版本」
- 顶栏按钮文案为「恢复此版本」，点击调 `restorePreview`
- 点侧栏 current 行 → `closePreview`，取消预览、回到当前稿编辑（不升版）

### 六、`DocumentVersionPanel` UI

桌面端放 `DocumentReview` 右侧窄栏，宽度约 `w-72`；移动端可折叠为「版本」抽屉。

**侧栏内容：**

```
版本历史                    [保存为新版本]
─────────────────────────────────
● v2  当前    另存 · 13:20        [备注]
  定稿前备份
  v1          生成   · 12:05        [备注]
```

- 「保存为新版本」：点击即 `POST checkpoint`，`isCheckpointing` 时 disabled 并显示 loading；**不弹备注表单**
- 列表项：版本号、`source_kind` 中文标签、时间；右侧 **「备注」** 按钮（带边框小标签样式，比来源行更显眼）
- 点击「备注」：在版本块内展开 textarea + 取消/保存；点击备注按钮不触发预览（`stopPropagation` 或拆成独立区域）
- 已保存备注：在来源/时间行下方显示用户备注文字（`line-clamp-2`）；**不展示 `content_preview` 等自动摘要**
- 当前项高亮；点击版本主区域（非备注按钮）进入预览

| source_kind | 展示文案 |
|-------------|----------|
| `generate` | 生成 |
| `optimize` | 优化 |
| `auto_save` | 编辑 |
| `checkpoint` | 另存 |
| `restore` | 恢复 |
| `import` | 导入 |

**备注与 checkpoint 分离：** checkpoint 只负责升版快照；用户想给某一版加说明时，事后点该版的「备注」按钮，调用 `PATCH .../note` 写入 `change_note`。任意版本（含 current、历史）均可备注。

**不要做的按钮：** 保存、定稿。

### 六点五、PRD 审查意见侧栏

仅 `docType === 'prd'` 时，版本侧栏下半段可折叠展示审查意见（`ReviewResultPanel`）。

**数据来源：** 当前聚焦版本（current 或预览中）的 `metadata.review`；仅 v1 且无 metadata 时回退 `session.prdReviewResult`（老数据迁移）。

**展示规则：**

| 版本来源 | 是否显示审查 |
|----------|--------------|
| `generate`（含重新生成） | ✅ 显示该次生成的 review |
| `optimize` / `auto_save` | ✅ 显示（为生成时 review，优化/手改后不刷新） |
| `checkpoint` / `restore` | ❌ 不显示 |

副标题固定文案：**「基于生成时审查，修改后仅供参考」**。

### 七、`DocumentReviewWithVersions`

新建组件，**对外暴露与 `DocumentReview` 几乎相同的 props**，并增加版本相关字段。`AppV2` 只使用该组件，不再直接拼 `useDocumentVersions` 与 `DocumentVersionPanel`。

```typescript
type DocumentReviewWithVersionsProps = {
  sessionId: string | undefined;
  docType: DocumentType;
  /** 当前工作稿正文，与 AppV2 state 双向绑定 */
  content: string;
  onContentChange: (content: string) => void;
  /** Job 已空闲时刷新版本列表；传入 jobGen 的优化/生成进行中标志 */
  jobIdle: boolean;
} & Omit<DocumentReviewProps, 'content' | 'onSaveEdit' | 'versionPanel' | 'isPreviewMode' | 'previewLabel' | 'onRestorePreview' | 'isRestoring'>;
```

**内部职责：**

1. 调 `useDocumentVersions({ sessionId, docType, editorContent: content, enabled: !!sessionId })`
2. 渲染 `DocumentVersionPanel`，绑定 `openPreview`、`checkpoint`、`saveVersionNote`、`refreshList` 所需回调
3. 计算 `displayContent = preview?.content ?? content`
4. `onSaveEdit`：预览态直接 return；否则 `onContentChange(value)`
5. `useEffect`：当 `jobIdle` 从 false 变 true 时 `refreshList()`，避免优化流式过程中频繁请求列表接口
6. 侧栏 `error`、`isLoadingList` 在 Panel 或组件顶部展示

**骨架示例：**

```tsx
export default function DocumentReviewWithVersions({
  sessionId,
  docType,
  content,
  onContentChange,
  jobIdle,
  ...reviewProps
}: DocumentReviewWithVersionsProps) {
  const versions = useDocumentVersions({
    sessionId,
    docType,
    editorContent: content,
    enabled: !!sessionId,
  });

  const prevJobIdle = useRef(jobIdle);
  useEffect(() => {
    if (!prevJobIdle.current && jobIdle) {
      void versions.refreshList();
    }
    prevJobIdle.current = jobIdle;
  }, [jobIdle, versions.refreshList]);

  return (
    <DocumentReview
      {...reviewProps}
      content={versions.preview?.content ?? content}
      isPreviewMode={!!versions.preview}
      previewLabel={
        versions.preview ? `预览 v${versions.preview.version_no}` : undefined
      }
      onRestorePreview={() => void versions.restorePreview().then((c) => c && onContentChange(c))}
      isRestoring={versions.isRestoring}
      onSaveEdit={(v) => {
        if (versions.preview) return;
        onContentChange(v);
      }}
      versionPanel={
        <DocumentVersionPanel
          versions={versions.versions}
          currentVersionNo={versions.currentVersionNo}
          isLoading={versions.isLoadingList}
          error={versions.error}
          isCheckpointing={versions.isCheckpointing}
          savingNoteVersionId={versions.savingNoteVersionId}
          onSelectVersion={versions.openPreview}
          onCheckpoint={() => versions.checkpoint()}
          onSaveVersionNote={(versionId, changeNote) =>
            versions.saveVersionNote(versionId, changeNote)
          }
          onRetry={versions.refreshList}
        />
      }
    />
  );
}
```

`generating-*` 页继续直接用 `DocumentReview`，不挂版本侧栏。

### 八、`DocumentReview` 轻改

仅增加布局与预览态 props，**不**在内部调版本 API：

```typescript
versionPanel?: React.ReactNode;
isPreviewMode?: boolean;
previewLabel?: string;
onRestorePreview?: () => void;
isRestoring?: boolean;
```

有 `versionPanel` 时布局为 flex：主编辑区 `flex-1`，侧栏 `flex-shrink-0`。

预览态下 textarea 只读，不触发 `onSaveEdit`。预览态下禁用优化；下载、复制可针对当前展示正文。

预览态顶栏显示 `previewLabel` 与「恢复此版本」按钮，点击 `onRestorePreview`；`isRestoring` 时按钮 loading。

### 十、与 debounce 自动保存的关系

不新增保存按钮。手改仍 `onContentChange` → `setPrdContent` → 现有 `debouncedSaveSession`。后端 save 同步 current 后，侧栏 `version_no` 不变，列表项在 `refreshList` 后更新。

交互约定：日常编辑自动保存到 current；需要留里程碑时，用户主动点「保存为新版本」触发 checkpoint。

### 十一、空状态

| 状态 | UI |
|------|-----|
| 尚无版本 | 侧栏「暂无版本历史」；「保存为新版本」隐藏或 disabled |
| 仅有 v1 | 列表一行；checkpoint 后出现 v2 |
| 加载失败 | 侧栏小字错误 + 重试 |

### 十二、验收标准

- `review-prd` 生成完成后侧栏显示 v1，标签「生成」
- 连续优化两次：仍 v1，正文已更新；列表 preview 随 `refreshList` 更新
- 再次点击生成 PRD / 接口文档 / 提示词并完成 Job：升新版，旧版进历史
- PRD 重新生成后，侧栏显示新版审查意见；优化/手改后仍显示生成时 review，附「基于生成时审查」提示
- 手改 debounce 后刷新页面：正文保留，仍 v1
- 点「保存为新版本」：出现 v2 当前与 v1 历史；编辑器内容与 checkpoint 前一致；**不强制填写备注**
- 点某版「备注」：可补充说明；保存后侧栏显示备注文字；刷新后仍在
- 点 v1 预览：只读，优化按钮禁用；点「恢复此版本」后出现 v3（正文同 v1），v1、v2 仍在历史
- 预览时点侧栏 current 行：取消预览，回到 v2 编辑，不升版
- 三文档版本独立：PRD v2 不影响接口文档 v1
- `AppV2.tsx` 无 `useDocumentVersions`、无直接引用 `DocumentVersionPanel`
- `npm run build` 无类型错误
- `generating-*` 页无版本侧栏
