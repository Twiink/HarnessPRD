# 文档生命周期管理测试验收

## 测试准备

验收范围：

- 后端 `documents`、`document_versions` 模型与 6 个 Document API（含 restore、版本备注）
- Job 完成写入 current、Session save 自动同步、老 Session 迁移
- 前端版本侧栏、「保存为新版本」、每版「备注」、历史预览与「恢复此版本」

环境要求：

- `backend/.env` 配好 LLM，如 DeepSeek
- 后端 `uvicorn main:app --reload` 已启动
- 前端 `npm run dev` 已启动，走 `/v2` 结构化流程
- 浏览器 DevTools Network 可观察请求

**不在本次验收范围：** 定稿、diff 对比、PRD 变更过期提示、RAG 入库、v1 `App.tsx`。

---

## 一、后端 API 测试

### 1. 新 Session 文档槽位为空

先 `POST /api/session/save` 创建 session，记下 `id`。

```bash
curl -s http://127.0.0.1:8000/api/session/<SESSION_ID>/documents | jq
```

预期：`items` 含 `prd`、`api-docs`、`prompts` 三项；`current_version_id` 均为 null。

### 2. 版本列表为空

```bash
curl -s http://127.0.0.1:8000/api/session/<SESSION_ID>/documents/prd/versions | jq
```

预期：`versions: []`。

### 3. checkpoint 无 current 时应失败

```bash
curl -s -X POST http://127.0.0.1:8000/api/session/<SESSION_ID>/documents/prd/versions/checkpoint \
  -H "Content-Type: application/json" \
  -d '{}'
```

预期：400，提示无内容可保存，或要求传入 content。

### 4. 产生 v1 后列表可见

走 UI 或 Job API 生成 PRD 完成后：

```bash
curl -s http://127.0.0.1:8000/api/session/<SESSION_ID>/documents/prd/versions | jq
```

预期：

- 一条 `version_no: 1`，`is_current: true`
- `source_kind` 为 `generate`
- `content_preview` 非空

### 5. checkpoint 升版

在已有 v1 前提下：

```bash
curl -s -X POST http://127.0.0.1:8000/api/session/<SESSION_ID>/documents/prd/versions/checkpoint \
  -H "Content-Type: application/json" \
  -d '{"content": "# PRD: 测试\n\n正文"}' | jq
```

预期：返回 `version_no: 2`。

再次 `GET .../versions`：

- v2 `is_current: true`，`source_kind: checkpoint`
- v1 仍在列表，`is_current: false`

### 6. 版本详情含 metadata

```bash
curl -s http://127.0.0.1:8000/api/session/<SESSION_ID>/documents/prd/versions/<V1_ID> | jq
```

预期：含完整 `content`；若经 Job 生成，`metadata.run_summary` 或 `metadata.review` 至少有一项存在。

### 7. 非法 doc_type

```bash
curl -s http://127.0.0.1:8000/api/session/<SESSION_ID>/documents/foo/versions
```

预期：400。

### 8. restore 升新版

在已有 v1（生成）、v2（checkpoint 当前）前提下：

```bash
curl -s -X POST http://127.0.0.1:8000/api/session/<SESSION_ID>/documents/prd/versions/<V1_ID>/restore | jq
```

预期：

- 返回 `version_no: 3`，`content` 与 v1 一致
- `GET .../versions`：v3 `is_current: true`，`source_kind: restore`
- v1、v2 仍在列表，正文与恢复前一致

对 current 版 restore 应 400。

### 9. 版本备注 PATCH

在已有 v1 前提下：

```bash
curl -s -X PATCH http://127.0.0.1:8000/api/session/<SESSION_ID>/documents/prd/versions/<V1_ID>/note \
  -H "Content-Type: application/json" \
  -d '{"change_note": "定稿前备份"}' | jq
```

预期：

- 返回 `change_note: "定稿前备份"`
- `GET .../versions` 对应项含 `change_note`
- v1 `content` 与 `version_no` 不变

再次 PATCH 传 `{"change_note": ""}` 或空字符串，备注应被清空。

## 二、Job 写入 current 版本

### 1. 首次生成 PRD 产生 v1

1. 走澄清 → 生成 PRD Job
2. 完成后查 DB 或 API

预期：

- `document_versions` 仅 1 行，`version_no=1`
- `session_data.prdContent` 与 v1 `content` 一致

### 2. 连续两次优化不升版

1. 在 `review-prd` 优化两次，指令不同
2. 每次完成后 `GET .../prd/versions`

预期：

- 始终只有 `version_no: 1` 为 current，除非中间做过 checkpoint 或重新生成 PRD
- `content` 为最后一次优化结果
- `metadata.run_summary` 反映最后一次 Job

### 2b. 重新生成 PRD / 接口文档 / 提示词会升版

1. 已有 PRD v1 后，从澄清对话或表单再次触发「生成 PRD」并完成 Job
2. `GET .../prd/versions`

预期：

- 出现 v2 为 current，`source_kind: generate`
- v1 仍在列表，正文为首次生成结果
- 对接口文档、提示词重复「生成」按钮，行为相同（各自版本链独立）

### 3. Job 失败保留 partial

断网或无效 key 使 Job `failed`，且已有部分 `draft_content`。

预期：current 有 partial 文本；Session 镜像一致；不凭空多出新版号。

## 三、Session 自动保存

### 1. 手改 debounce 不升版

1. 进入 `review-prd`，在正文末尾加唯一标记，如 `<!-- manual-test -->`
2. 停笔等待 2 秒，超过 debounce
3. `GET .../prd/versions`

预期：仍 v1；刷新页面标记仍在。

4. 用 SQLite 或 API 查 v1 `content` 含该标记。

### 2. 自动保存不触发 checkpoint

观察 Network：手改期间应只有 `POST /api/session/save`，不应自动 `POST .../checkpoint`。

## 四、老 Session 迁移

### 1. 模拟旧数据

用 `POST /api/session/save` 写入仅含 `prdContent` 的 session：

```json
{
  "session_data": {
    "viewState": "review-prd",
    "prdContent": "# 旧 PRD\n\n迁移测试"
  }
}
```

### 2. 首次加载

`GET /api/session/<ID>` 或 UI 打开该方案。

预期：

- 出现 `documents(prd)` 与 v1
- `source_kind` 为 `import`
- 正文与旧 `prdContent` 一致

## 五、前端版本侧栏与 checkpoint

### 1. 生成后展示 v1

完成 PRD 生成进入 `review-prd`。

预期：

- 侧栏显示 v1，标签「生成」或「当前」
- 主编辑区可编辑

### 2. 优化两次仍 v1

连续优化两次。

预期：

- 侧栏仍一行 v1（未重新生成、未 checkpoint）
- 正文已变，版本号不变

### 2b. 重新生成会升版

1. 已有 PRD v1，再次点击「生成 PRD」并完成
2. 或已有接口文档 v1，从 PRD 页再次「生成接口文档」并完成

预期：

- 侧栏出现 v2 当前，v1 在历史
- 正文为本次生成结果

### 3. 保存为新版本

1. 点「保存为新版本」
2. 观察 Network：`POST .../checkpoint`

预期：

- 侧栏 v2 为当前，v1 在历史
- 编辑器内容与不点按钮前一致
- 无额外「保存」按钮

### 4. 预览与恢复历史版本

1. 点击侧栏 v1

预期：

- 编辑区只读，提示预览 v1
- 「优化文档」禁用
- 顶栏按钮为「恢复此版本」（非「返回当前版本」）

2. 点击「恢复此版本」

预期：

- `POST .../versions/<V1_ID>/restore`
- 侧栏出现 v3 当前，v1、v2 在历史
- 编辑区正文与 v1 一致，可编辑
- `session_data.prdContent` 与 v3 一致

3. 再次预览 v1 但不恢复，点侧栏 v3 当前

预期：取消预览，回到 v3 编辑，不升版

### 5. 预览态手改不污染

预览 v1 时尝试改字，应只读。

预期：`prdContent` state 与 v2 current 不变。

### 6. 版本备注 UI

1. 在侧栏 v1 点「备注」，输入「定稿前备份」并保存

预期：

- Network：`PATCH .../versions/<V1_ID>/note`
- 版本块下方显示备注文字
- 侧栏不展示正文 `content_preview` 自动摘要

2. 再次点「备注」修改或清空，保存后展示同步更新

3. 点「备注」不应触发进入预览；点版本主区域仍可预览

4. F5 刷新后备注仍在

### 7. PRD 审查意见展示

1. 首次生成 PRD 完成后，侧栏下半段显示审查意见，含「基于生成时审查，修改后仅供参考」
2. 重新生成 PRD（升 v2）后，审查意见更新为 v2 的 review
3. 优化 PRD 不升版：审查区仍显示，内容为生成时 review（未重新跑 Review Agent）
4. 「保存为新版本」后的 checkpoint 版：侧栏无审查区
5. 预览带 review 的历史 generate 版：显示该版 review

## 六、三文档版本独立

1. 完成 PRD → 生成接口文档 → 各 checkpoint 一次

预期：

- PRD 侧栏有自己的 v1、v2
- 接口文档侧栏有自己的 v1、v2，版本号不与 PRD 对齐
- 提示词未生成时侧栏空或「暂无版本」

---

## 七、刷新与重连

### 1. checkpoint 后刷新

F5 后仍在 `review-prd`。

预期：侧栏 v1、v2 关系保持；current 正文正确。

### 2. 优化 Job 中刷新

优化过程中刷新页面。

预期：仍能重连优化流；完成后 current 更新，version_no 不增加。

### 3. run_summary 刷新不丢

PRD 生成完成后展开 RunSummary，刷新页面。

预期：v1 详情 API 中 `metadata.run_summary` 有数据。UI 若尚未从 metadata 恢复展示，至少 API 层数据完整。
