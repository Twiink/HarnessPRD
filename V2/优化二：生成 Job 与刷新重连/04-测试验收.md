# 生成 Job 与刷新重连测试验收

## 测试准备

验收范围：

- 后端 Generation Job（PRD / 接口文档 / 提示词）
- 前端 Job 订阅与刷新重连
- 文档优化 Job（`optimize-prd` / `optimize-api-docs` / `optimize-prompts`）

环境要求：

- `backend/.env` 配好 LLM（如 DeepSeek）
- 后端 `uvicorn main:app --reload` 已启动
- 前端 `npm run dev` 已启动，能打开 `/v2` 结构化流程
- 浏览器 DevTools Network 可观察 SSE

**不在本次验收范围：** 澄清对话流式 Job 化、Celery 多 Worker、文档 revision 生命周期。

---

## 一、后端 API 测试（生成 Job）

### 1. 创建 PRD Job

先通过 UI 或 `/api/session/save` 创建一个 session，记下 `id`。

```bash
curl -s -X POST http://127.0.0.1:8000/api/jobs \
  -H "Content-Type: application/json" \
  -d '{
    "session_id": "<SESSION_ID>",
    "artifact": "prd",
    "payload": {
      "requirements_summary": { "product_name": "测试", "product_goal": "测试", "target_users": ["用户"], "platform": "Web", "mvp_features": [] },
      "conversation_messages": []
    }
  }'
```

预期：返回 `{ "job_id": "..." }`；DB 中 `generation_jobs.status` 变为 `running`。

### 2. SSE 首条为 snapshot

```bash
curl -N http://127.0.0.1:8000/api/jobs/<JOB_ID>/stream
```

预期：

1. 第一条 `type: snapshot`，含 `phase`、`draft_content`（可为空字符串）
2. 随后 `phase: writer_started`、`text_delta`…
3. 结束前有 `done`、`run_summary`、`[DONE]`

### 3. 断开连接后 Job 继续

1. 启动 stream 后在 Writer 阶段 `Ctrl+C` 断 curl
2. 等待几秒后 `GET /api/jobs/<JOB_ID>`

预期：`status` 最终为 `completed`（或至少 `draft_content` 比断开时更长），证明 **disconnect 未 cancel 任务**。

### 4. 重复创建 running Job

同一 `session_id` 在 PRD 仍 `running` 时再 `POST /jobs` artifact=prd。

预期：409 或返回已有 jobId（与 `create_job` 实现约定一致），**不应**出现两个并行 PRD Job。

## 二、PRD 生成 — 正常路径（不刷新）

1. `/v2` 填示例表单 → 澄清 → 生成 PRD
2. 观察 `generating-prd`

预期：

1. Stepper：起草 → 审查 →（可能）修订
2. Writer / Rewrite 阶段打字机出字
3. Review 阶段有 hint，不像卡死
4. 进入 `review-prd`，正文完整
5. Session 中 `activeJobId` 为 null

---

## 三、PRD 生成 — 刷新重连

每种场景：**开始生成后刻意刷新一次**（F5），再观察。

### 1. Writer 阶段刷新

预期：

1. 刷新后仍在 `generating-prd`（**不是**澄清、不是空 review）
2. **已生成部分立刻显示**（不是从空白重新打字）
3. 稍后有新字继续追加（打字机仅针对新 chunk）
4. 最终正常进入 `review-prd`

### 2. Review 阶段刷新

在 Stepper 第二步、正文已完整时刷新。

预期：

1. `generating-prd`，全文静态展示
2. Stepper 在「机器审查」
3. 等待后进入 review（或进入 Rewrite 再完成）
4. **不应**跳回 `chatting`

### 3. Rewrite 阶段刷新

若本次生成触发修订，在 Rewrite 流式过程中刷新。

预期：

1. 仍 `generating-prd`
2. 已有 v2 partial 或 v1 可见（与实现约定一致，至少不空白）
3. 重连后继续完成，进入 `review-prd`

### 4. 已完成后再刷新

Job 已 `completed`，人在 `review-prd` 时刷新。

预期：

1. 直接 `review-prd`
2. 全文静态展示，**无打字机、无 Stepper**

## 四、接口文档与提示词（生成）

各走一遍主流程 + **生成中刷新一次**。

### 接口文档

1. PRD 审阅页 → 生成接口文档
2. 流式过程中刷新

预期：回到 `generating-api-docs` 或带 draft 的 review-api-docs；重连后继续；完成后 `review-api-docs`。

### 提示词

1. 生成提示词，流式中刷新

预期：同上，对应 `generating-prompts` / `review-prompts`。

## 五、失败与 partial（生成 Job）

### 1. 模拟失败（可选）

临时让 LLM 配置无效或 payload 缺字段，创建 Job。

预期：

1. Job `status=failed`
2. 前端落在 review 页，保留已有 `draft_content`（若有）
3. 有可读错误信息

### 2. 服务重启（V1 约定）

PRD 生成中重启后端。

预期（V1）：

1. Job 标记 `failed`，错误含「中断」类说明
2. Session 保留最后 draft
3. 刷新后不再自动续跑，用户可看到 partial 并手动重新生成

## 七、文档优化 Job

**前置：** `optimize-*` Job 已实现；旧 `optimize-document-stream` 可保留但 AppV2 不再调用。

### 1. 后端 API — 创建优化 Job

在已有 PRD 内容的 session 上：

```bash
curl -s -X POST http://127.0.0.1:8000/api/jobs \
  -H "Content-Type: application/json" \
  -d '{
    "session_id": "<SESSION_ID>",
    "artifact": "optimize-prd",
    "payload": {
      "doc_type": "prd",
      "current_content": "# 测试 PRD\n\n...",
      "instruction": "补充技术规格章节",
      "context": ""
    }
  }'
```

预期：

1. 返回 `{ "job_id": "..." }`
2. `generation_jobs.artifact` 为 `optimize-prd`，`phase=generating`
3. `curl -N .../stream` 首条 `snapshot`，随后 `text_delta`，结束有 `done` + `run_summary`

### 2. PRD 优化 — 正常路径（不刷新）

1. 进入 `review-prd`，点击「优化文档」，输入指令并确认
2. 观察页面

预期：

1. **仍在 `review-prd`**（不切 `generating-prd`）
2. 正文区域流式更新（`isOptimizing` 只读态）
3. **无** PRD 三阶段 Stepper
4. 完成后正文为优化结果，可编辑
5. `activeJobId` 为 null
6. Network 可见 `POST /api/jobs`（artifact=`optimize-prd`），非 `optimize-document-stream`

### 3. PRD 优化 — 刷新重连

优化流式过程中 **F5 刷新**。

预期：

1. 刷新后仍在 **`review-prd`**（不是澄清、不是 `generating-prd`）
2. **已优化部分立刻显示**（snapshot），不是回到优化前原文
3. 稍后有新字继续追加
4. 完成后全文为优化结果
5. **不应**出现「整篇从优化前重新流式」的假重播

### 4. 优化完成后再刷新

优化 Job 已 `completed`，人在 `review-prd`。

预期：静态全文，无打字机，无优化中 loading。

### 5. 接口文档与提示词优化

在 `review-api-docs`、`review-prompts` 各做一次优化 + **优化中刷新一次**。

预期：与 PRD 优化相同——保持 review 页、snapshot 秒出、继续追加、完成后更新对应 content。

### 6. 与生成 Job 互斥

1. PRD 生成 `running` 时，再点「优化文档」  
   或 optimize-prd `running` 时，再点「生成 PRD」

预期：409 或前端友好错误，**不**出现两个并行 Job 写同一文档。

### 7. 优化失败与 partial

模拟 LLM 失败或中断 optimize Job。

预期：

1. Job `failed`，review 页展示错误
2. 若已有 `draft_content`，保留 partial（不丢优化进度）
3. `activeJobId` 清空

### 8. run_summary

优化完成后，token 折叠面板（若 session 内未刷新）展示本次 `run_summary`；`run_type` 含 `optimize_document`。
