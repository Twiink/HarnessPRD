# 接口文档生成规范

当任务是基于已确认的 PRD 生成 HTTP 接口文档时，使用本 skill。

## 输入

- PRD 正文（必填）
- 澄清对话摘要（可选）

## 输出

- 中文 Markdown 接口文档
- 按 **核心接口** 与 **边缘接口** 组织

## 规则

1. 路径命名、请求/响应结构、错误码遵循 `references/team-api-guidelines.md`。
2. 参数表、响应 JSON、错误处理等写法参考 `references/history-*.md` 中的历史示例。
3. **不要把规范原文机械堆砌进正文**，应内化为具体接口设计结果。
4. 区分 MVP 必须接口（核心接口）与辅助接口（边缘接口）。
5. 路径采用 RESTful 风格，默认使用 `/api/v1/...`，除非 PRD 另有说明。
