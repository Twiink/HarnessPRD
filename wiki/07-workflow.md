# 核心工作流说明

## 完整用户旅程

```
1. 填写表单（可选）
       ↓
2. AI 对话引导（需求澄清）
       ↓
3. 生成 PRD → 审核/编辑/优化 → 确认
       ↓
4. 生成接口文档（可跳过）→ 审核/编辑/优化 → 确认
       ↓
5. 生成 AI 提示词 → 审核/编辑/优化 → 确认
       ↓
6. 下载所有文档
```

任何阶段都可以选择"结束任务"直接跳到下载页。

---

## 阶段一：需求收集表单

用户填写产品信息表单，分两层：

**基础问题（10 个，必填）**
| 字段 | 说明 |
|------|------|
| 产品名称 | 项目标识 |
| 解决的问题 | 核心痛点 |
| 目标用户 | 使用人群 |
| MVP 核心功能 | 3-5 个核心功能 |
| v2 功能规划 | 后期迭代方向 |
| 页面数量 | 大概几个页面 |
| 页面风格 | 视觉设计方向 |
| 平台类型 | Web / 小程序 / App |
| 登录需求 | 是否需要用户账号 |
| 数据存储 | 是否需要数据库 |

**高级问题（5 个，可选）**
| 字段 | 说明 |
|------|------|
| 技术栈偏好 | 指定框架/语言 |
| 第三方 API | 如支付、地图等 |
| 安全要求 | 数据安全级别 |
| 性能要求 | 并发、响应时间等 |
| 部署方式 | 云服务、自托管等 |

用户也可以跳过表单，直接在文本框里描述想法开始对话。

**表单提交后：**
后端将表单数据格式化为结构化文本，与 SYSTEM_PROMPT 一起构建初始消息，启动 AI 对话。

---

## 阶段二：AI 需求对话

AI 扮演资深产品经理，通过双向对话帮用户想清楚产品需求。

**AI 对话策略：**
1. 先确认理解了用户的核心想法
2. 识别最需要深入的 1-2 个关键点
3. 提出具体建议或选项，而不是开放式问题
4. 每轮聚焦，不一次追问多个问题
5. 适时总结已确认内容
6. 信息充足时，主动提议生成 PRD

**用户可以随时：**
- 继续输入补充信息
- 点击"生成 PRD"进入下一阶段

**触发生成 PRD 的时机：**
前端要求至少 2 条用户消息后才显示"生成 PRD"按钮（避免信息过少就生成）。

---

## 阶段三：PRD 审核

点击"生成 PRD"后，系统将完整对话历史发给 LLM，生成标准化 PRD。

**PRD 结构（6 章）：**
1. 产品概述（名称、核心问题、目标用户、平台）
2. 功能需求（MVP 功能表格 + v2 规划列表）
3. 页面设计（页面结构 + 视觉风格）
4. 技术规格（平台、认证、存储、技术栈建议）
5. 非功能需求（性能、安全、可用性）
6. 项目范围（在范围内 / 不在范围内）

**生成参数：** `temperature=0.3`（低随机性，保证结构完整性）

**可选本地模板：** 如果 `core/prd_template.md` 存在且非空，AI 会参考其格式（内容以对话为准）。

**审核阶段用户操作：**
- **直接编辑**：textarea 可以直接修改，实时保存
- **AI 优化**：输入自然语言指令（如"把技术栈改成 Vue + FastAPI"），AI 输出优化后的完整文档
- **复制**：一键复制全文
- **继续**：进入接口文档生成
- **跳过接口文档**：直接进入提示词生成
- **结束任务**：下载 PRD 并结束

---

## 阶段四：接口文档生成（可跳过）

以 PRD 内容 + 对话历史为输入，设计 RESTful API。

**接口文档结构：**
- **核心接口**：MVP 必须的接口（CRUD + 核心业务逻辑）
- **边缘接口**：辅助功能（配置、统计、管理等）

每个接口包含：
- HTTP Method + Path
- 功能说明
- 请求参数（表格：参数名、类型、必填、说明）
- 响应示例（JSON）

**设计原则：** RESTful 规范，使用标准 HTTP 方法，路径语义清晰。

**审核阶段用户操作：**同 PRD 阶段，可编辑、优化、复制，然后进入提示词生成或结束任务。

---

## 阶段五：AI 提示词套件生成

以 PRD + 接口文档（可选）为输入，生成 5 类 Claude Code 可用的提示词。

**5 类提示词：**

| 类别 | 用途 |
|------|------|
| 1. 项目总览提示词 | 开始新项目时，让 AI 理解全局背景和技术栈 |
| 2. 功能开发提示词 | 针对每个 MVP 功能各一个，引导逐步实现 |
| 3. 接口实现提示词 | 按接口文档实现后端逻辑（若有接口文档） |
| 4. 前端开发提示词 | 实现前端界面和交互，包含设计风格要求 |
| 5. 代码审查提示词 | 检查代码规范、安全性、性能 |

每个提示词**自包含**：包含足够的背景上下文，不依赖外部文档也能直接使用。

**生成参数：** `temperature=0.5`（适度创意，生成质量更高的提示词）

---

## 阶段六：完成页（下载）

展示所有已生成的文档，每个文档独立下载按钮。

**下载格式：** Markdown 文件（`.md`）

**文件命名：**
- `prd.md`
- `api-docs.md`  
- `prompts.md`

**下载实现（前端）：**
```javascript
const blob = new Blob([content], { type: 'text/markdown' })
const url = URL.createObjectURL(blob)
const a = document.createElement('a')
a.href = url
a.download = `${filename}.md`
a.click()
URL.revokeObjectURL(url)
```

## 文档优化工作流

在任意文档审核阶段，用户可以输入自然语言指令优化文档：

```
用户输入："把技术栈建议改成 Next.js + Supabase"
     ↓
POST /api/conversation/optimize-document-stream
{ doc_type: "prd", current_content: "...", instruction: "..." }
     ↓
AI 输出优化后的完整文档（流式）
     ↓
前端替换 streamingContent，完成后更新 prdContent
```

优化时：
- textarea 变为只读，显示"优化中..."
- 流式输出完成后，文档内容更新为优化版本
- 用户可以继续再次优化或手动编辑

---

## 会话恢复

用户关闭/刷新页面后，重新打开会自动恢复会话：
- 对话历史恢复
- 已生成的文档内容恢复
- 回到上次的阶段（生成中状态降级处理）

点击"重新开始"清除所有会话数据，回到表单页。
