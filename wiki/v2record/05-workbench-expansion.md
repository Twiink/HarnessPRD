# `/v2` 从单一路径升级成工作台

> 这篇记录了 `/v2` 的一次关键升级：从"只能从头走到尾的单条流程"，变成"可以从任意环节进入、可以跳步的工作台"。这个变化看起来只是多了几个按钮，但背后的系统复杂度变化其实相当大。

---

## 1. 升级之前：`/v2` 还是一条单行道

第一版 `/v2` 虽然引入了结构化录入和澄清对话，但流程本质上还是线性的：

```text
结构化输入 -> 澄清 -> PRD
```

只能从头走，不能跳步，不能从中间进。

用户很快就提出了更多需求：

- v2 也要能生成接口文档和提示词
- 如果我已经有了 PRD，能不能直接从 PRD 开始？
- 如果我只想验证提示词生成的效果，能不能直接跳过前面？

这些需求背后有一个共同的逻辑：**真实用户不总是从零开始的。**

---

## 2. 类比：从"单条流水线"到"弹性工作台"

**原来**像一条流水线：只有一个入口，按顺序走，不能跳步，不能返回。

**升级后**像一个工作台：有多个入口，可以从任意节点进入，可以前进也可以后退，可以随时暂停或结束。

---

## 3. 工作台升级做了什么

### 3.1 三种入口模式

新增了三种进入方式：

| 模式 | 适合什么场景 |
|------|-------------|
| 结构化需求 | 从头开始梳理需求，走完整流程 |
| 从 PRD 开始 | 已经有 PRD，想继续生成接口文档和提示词 |
| 从提示词开始 | 只想生成或验证提示词部分 |

### 3.2 支持中间环节直达

用户可以直接贴入：
- 已有的 PRD
- PRD + 接口文档

系统从"你当前所在的阶段"开始继续，不强制从头跑一遍。

### 3.3 多阶段输出串联

`/v2` 现在涵盖完整链路：

```text
PRD -> 接口文档 -> 提示词
```

三个阶段可以按顺序连续生成，也可以只生成其中某几个。

### 3.4 顶部阶段导航

增加了顶部的阶段导航条，用户随时都能看到：
- 当前在哪个阶段
- 哪些阶段已经完成
- 哪些阶段可以返回

---

## 4. 为什么这个方向是对的

现实中的用户有三种情况：

1. **从头开始型**：什么都没有，需要从录需求开始走完整流程
2. **中途接入型**：已经有 PRD，只需要后半段
3. **验证型**：想验证某个阶段的效果，不想每次都重新走一遍

如果 `/v2` 不能支持跳步，它就只能服务第一种用户，对后两种用户来说只是"更复杂的向导"，而不是真正的工作台。

---

## 5. 工作台化之后带来的新工程要求

一旦支持跳步、多入口，系统就必须能处理一些原本不需要考虑的事情：

- **返回上一步**：当前阶段的操作可以撤销，回到上一个状态
- **结束当前任务**：用户可以随时中止，不必走完全部流程
- **刷新后恢复**：页面刷新不应该丢失当前进度
- **阶段跳转**：从一个阶段切换到另一个阶段，状态要正确

这也是为什么后续需要继续补充：
- `localStorage` 会话持久化（解决刷新丢失问题）
- 统一的"结束任务"逻辑
- 更清晰的"返回上一步"行为

---

## 6. 这轮迭代的核心收获

这一轮最大的收获不是多了几个按钮，而是明确了 `/v2` 的定位：

> `/v2` 不是"新版页面"，而是 skill 运行时的前端工作台。

一旦接受这个定位，很多设计决策就变得自然：

- 中间态必须可见（因为工作台要让用户随时知道自己在哪）
- 过程必须可中断（因为工作台不能强迫用户一次走完）
- 任意阶段都应该是可进入节点（因为工作台本身就是弹性的）

这个定位的确立，比"多了三个功能"更重要。
