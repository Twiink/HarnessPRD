# `/v2` 从单一路径升级成工作台

## 1. 最初的 `/v2` 还是太像流程页

虽然 `/v2` 一开始已经独立出来，但它本质上还是一条主路径：

```text
结构化输入 -> 澄清 -> PRD
```

很快用户就提出了更强的需求：

- v2 也要包含 v1 后面的能力
- 要能生成接口文档
- 要能生成提示词
- 还要支持从中间环节直接开始

这一步很关键，因为它把 `/v2` 从“一个新页面”推成了“一个工作台”。

## 2. 工作台升级做了什么

### 2.1 入口模式

增加了三种模式：

- 结构化需求
- 从 PRD 开始
- 从提示词开始

### 2.2 中间环节直达

用户可以直接贴：

- PRD
- PRD + 接口文档

然后从后半段开始。

### 2.3 多阶段输出

新增并串联了：

- PRD
- 接口文档
- 提示词

### 2.4 阶段导航

顶部增加了阶段导航，工作台感更强。

## 3. 为什么这是正确方向

因为真实用户并不总是从头开始：

- 有人已有 PRD，只想继续
- 有人有旧项目文档，只想生成提示词
- 有人只是来验证 skill 后半段是否好用

如果 `/v2` 不能跳步，它就仍然只是“更复杂的向导”。

## 4. 工作台化之后的新要求

一旦变成工作台，系统就必须支持：

- 返回上一步
- 结束任务
- 刷新恢复
- 阶段跳转

这也是为什么后面还继续补了：

- localStorage 会话持久化
- 统一的“结束任务”
- 更清晰的“返回上一步”

## 5. 这轮迭代的核心收获

这一轮最大的收获不是多了几个按钮，而是明确了一件事：

> `/v2` 不是“新版页面”，而是 skill 运行时前端。

一旦接受这个定位，很多后续设计都会变得自然：

- 中间态必须可见
- 过程必须可中断
- 任意阶段都应该是可进入节点
