# JSON 与运行时问题实录

> 这篇记录的是开发过程中最"折磨人"的一类问题：不是功能设计错了，也不是需求没想清楚，而是一些藏在技术层的坑——AI 输出的数据格式不合法、服务进程没有加载最新代码、Prompt 边界没有隔离好。这类问题的共同特点是"症状在前端，根因在别处"。

---

## 1. 为什么这类问题最折磨人

在 `/v2` 开发中，最棘手的问题不是页面 UI 做得不好看，而是这几类：

- AI 生成的 JSON 格式不合法，导致解析失败
- 后端代码已经更新，但运行的还是旧逻辑（服务没重启）
- 流程控制出现了意料之外的行为（比如澄清阶段就提前生成了 PRD）

这类问题的共同点是：

> 前端只看到"操作失败了"，但背后的真实原因完全不同。

排查这类问题需要同时关注多个层面，不能只盯着报错信息。

---

## 2. 典型问题一：服务没重启

### 什么情况？

有一次，错误日志显示代码还在执行 `json.loads(content)`，行号也对应旧代码文件里的那一行。

但工作区里的文件已经改成了 `_extract_json_object(content)`，明明改过了。

**实际原因**：后端服务的进程没有重新启动，内存里运行的还是旧代码，磁盘上的新文件根本没被加载。

### 白话理解

想象你把一份合同打印出来改了，但对方手里拿的还是上一版——他看的和你看的不是同一份文件。

### 经验教训

- 看报错的 traceback 时，要同时对比"错误里提到的行号"和"当前文件实际的内容"
- 不要默认"代码改了就等于服务在跑新逻辑"——修改文件之后一定要重启服务
- 如果排查很久发现症状和代码对不上，先重启服务再试一次

---

## 3. 典型问题二：AI 输出的 JSON "看起来像但其实不是"

### 什么情况？

出现了这样的错误：

```text
json.decoder.JSONDecodeError: Expecting ',' delimiter
```

### 什么是 JSON？（给非技术读者）

JSON 是一种机器能直接读取的格式化数据，类似于这样：

```json
{
  "功能名称": "生成文案",
  "优先级": "高",
  "描述": "用户输入关键词后，AI 生成一段朋友圈文案"
}
```

每个字段和值之间用 `:` 分隔，多个字段之间用 `,` 隔开，整体用 `{}` 包裹。格式必须完全正确，机器才能读懂——差一个逗号或多一个引号，就会解析失败。

### 为什么 AI 会输出"不合法的 JSON"？

AI 是为了让**人**看懂而优化的，不是为了满足机器的语法要求。当 AI 生成 JSON 时，可能出现：
- 少了一个逗号
- 引号没有正确转义
- 中文内容里混入了特殊字符
- 输出前后有多余的解释文字（比如"以下是回填结果："）

这比"完全不输出 JSON"更麻烦，因为第一眼看起来"格式差不多"，但机器解析就是会失败。

---

## 4. 三层兜底策略

为了应对 AI 输出的 JSON 可能有问题，设计了三层容错：

### 第一层：直接解析

先直接尝试 `json.loads(content)`，大多数情况能过。

### 第二层：提取并清理再解析

如果直接解析失败，尝试：
- 去掉 ` ```json ``` ` 代码围栏
- 去掉输出前后的解释文字
- 从第一个 `{` 到最后一个 `}` 截取对象

再试一次解析。这能处理"内容本身合法，但被多余文字包裹"的情况。

### 第三层：让 AI 自修复

如果前两层都失败了，把有问题的输出发给 AI，让它做一轮：

> 把这段内容修复成合法的 JSON 对象，只输出 JSON，不要有任何其他内容。

**白话说**：相当于让 AI "自己改卷"，虽然多了一次请求，但比直接报错要好很多。

---

## 5. 错误返回策略的改进

最初，JSON 解析失败会直接抛出 500 错误，前端只看到"请求失败"，完全不知道发生了什么。

改进后，失败时不再只抛裸异常，而是返回：
- 更可读的错误描述
- **原始输出片段**（AI 到底说了什么）
- **修复尝试的输出片段**（修复轮又输出了什么）

这样不管是在前端界面还是服务日志里，都能快速定位问题出在哪个环节。

## 6. 典型问题三：Prompt 边界缺失

### 什么情况？

有一次发现一个奇怪现象：澄清阶段还没结束，AI 就提前生成了 PRD。

**排查结果**：`/v2` 的澄清对话最初还在复用旧版的系统 Prompt，而旧 Prompt 里明确写着"当信息足够时，生成 PRD"。

AI 按照 Prompt 的指令，在澄清过程中觉得"信息差不多了"，就自动生成了 PRD。

### 为什么这个问题难发现？

因为看起来是"AI 行为异常"，但实际上 AI 是在按 Prompt 的规则执行——只是这个 Prompt 不应该被用在澄清阶段。

### 核心教训

> 工作流的阶段控制不能只靠前端按钮，**必须靠 Prompt 边界**来保证。

每个阶段都应该有专属的系统 Prompt，明确限定"这个阶段能做什么、不能做什么"。否则 AI 会按照旧有的通用指令行事，产生意料之外的行为。

---

## 7. 这轮问题留下的经验

### 7.1 任何依赖 AI 输出 JSON 的系统，都必须假设 JSON 会失败

不能把 AI 当成语法完美的机器。必须提前设计好容错策略，而不是遇到错误再想。

### 7.2 运行时可观测性比"猜测模型意图"更重要

如果系统能够暴露"AI 到底输出了什么"，排查效率会高出几倍。看不到原始输出，就只能瞎猜。

### 7.3 多阶段工作流必须有专用 Prompt

"澄清阶段只澄清，生成阶段才生成"——这种阶段边界不能靠用户理解，必须靠系统的 Prompt 约束来保证。
