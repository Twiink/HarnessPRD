# `/v2` 开发总结与复盘

## 1. 这次开发真正完成了什么

从结果上看，`/v2` 并不只是多了一个页面，而是把整个项目推向了一个新的架构阶段。

它完成了这些关键变化：

1. 从“Prompt 驱动页面”升级成“Skill 驱动工作流”
2. 从“自然语言输入优先”升级成“结构化输入优先”
3. 从“会话黑盒”升级成“中间态可视化”
4. 从“线性流程”升级成“可跳步工作台”

## 2. 哪些决策是明显正确的

### 2.1 新旧页面分离

没有直接改旧页面，而是单独做 `/v2`，这让整个试验成本和风险都低很多。

### 2.2 优先稳定性

用户一开始就明确提出“稳定可靠比体验更重要”，这让设计取向更清晰，也避免了很多无意义花活。

### 2.3 把回填做成显式确认

这是整个链路里最关键的一步，它让“结构化数据”成为真正的中心对象。

### 2.4 Skill 文件外置

把 skill 做成目录与文件，而不是写死在代码里，为后面平台化留出了空间。

## 3. 哪些问题最值得记住

### 3.1 模型会天然破坏 JSON

这是事实，不是偶发异常。

### 3.2 运行时状态比代码本身更容易误导人

文件改了，不等于服务跑的是新逻辑。

### 3.3 多阶段工作流必须有明确边界

否则澄清、生成、确认这些动作会互相串味。

### 3.4 工作台不是“多加几个按钮”

一旦支持跳步、恢复、回退，就已经是状态管理系统，不再只是页面切换。

## 4. 当前 `/v2` 的位置

现在的 `/v2` 可以被理解成：

- 产品层：新的高级工作台
- 架构层：skill-first 方案的第一个真实壳
- 工程层：未来通用 skill runtime 的前哨站

## 5. 这套方案还没有完成的地方

虽然已经很强了，但它仍然有明显后续空间：

- skill 注册中心还没做
- adapter 还没做
- schema 严格验证还不够
- 回填 patch 还不够细粒度
- 自动评估还没上线

## 6. 这次迭代最值得保留的经验

如果要总结成一句话，就是：

> 不要把“生成文档”当成一次模型调用，而要把它设计成一条可见、可控、可确认、可恢复的能力链路。

这是 `/v2` 真正留下来的东西。
