# `/v2` 工作台：为什么它不是“新版页面”，而是一个运行台

如果只从路由层看，`/v2` 似乎只是项目里新增了一个页面。  
但实际做着做着就会发现，它和旧版页面不是一个级别的东西。

旧版更像一条用户旅程：

```text
填表 -> 对话 -> PRD -> 接口文档 -> 提示词
```

而 `/v2` 更像一个工作台。

工作台和流程页最大的区别在于：

> 流程页强调“从头走到尾”，工作台强调“你当前在什么阶段，接下来可以怎么走，也可以从哪里重新进入”。

这也是为什么 `/v2` 后来越做越不像向导，反而越来越像一套 skill 运行时前端。

## `/v2` 为什么必须变成工作台

一开始的诉求其实很朴素：

- 结构化输入要更稳
- 对话要能补齐缺失信息
- 生成 PRD 要更可控

但很快就碰到现实使用场景：

- 有人已经有 PRD，只想继续生成接口文档
- 有人已经有 PRD 和接口文档，只想生成提示词
- 有人中途想停下来
- 有人刷新后希望还能接着做

如果 `/v2` 还是一个单一路径页面，它就承接不了这些场景。

所以它必须升级。

## 当前 `/v2` 的核心能力

现在的 `/v2` 已经不是单一路径，而是一个多入口工作台。

它支持三种进入方式：

### 1. 从结构化需求开始

这是最完整的一条链路：

```text
结构化录入
-> 澄清对话
-> 回填
-> diff
-> PRD
-> 接口文档
-> 提示词
```

### 2. 从 PRD 开始

如果你手上已经有 PRD，可以直接贴进去，然后：

- 进入 PRD 环节继续审核
- 或直接生成接口文档

### 3. 从提示词开始

如果你已经有：

- PRD
- 或 PRD + 接口文档

就可以直接进入后半段，不必再重复前面的收集过程。

## 为什么阶段导航很关键

工作台一旦有多个入口、多个中间态，就不能再靠“页面感知”让用户自己猜当前在哪。

所以 `/v2` 顶部后来补了阶段导航：

- 结构化需求
- 澄清对话
- PRD
- 接口文档
- 提示词

它不是为了好看，而是为了给整个工作流建立一种非常清晰的“方位感”。

用户一眼就能看见：

- 自己当前在哪
- 哪些阶段已经完成
- 哪些阶段可以回去
- 哪些阶段还没到

这对多阶段系统非常重要。

## 为什么 `/v2` 必须支持中断和恢复

只要你把系统做成工作台而不是一次性流程，就必须接受一个事实：

> 用户不一定会一口气做完。

所以 `/v2` 现在除了阶段切换，还额外支持：

- 返回上一步
- 结束当前任务
- `localStorage` 状态恢复

这几样东西一开始看像体验优化，后来会发现它们其实是工作台的基本盘。

否则用户每次刷新、每次犹豫、每次切出去再回来，整条链路都会断掉。

## 为什么说 `/v2` 已经像 skill runtime 的前端壳

这一点其实很有意思。

传统页面通常只是收集输入、展示输出。  
而 `/v2` 现在在做的事情明显更多：

- 对输入做结构化
- 显示 skill 中间态
- 承担用户确认
- 控制多阶段流转
- 负责恢复会话状态

这已经不只是“页面”，而更像一个让 skill 真正运行起来的外层工作台。

从这个角度看，`/v2` 的意义远不只是产品增强，而是在给 skill-first 架构做一个真正能用的前端容器。
