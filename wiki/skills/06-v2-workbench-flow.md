# `/v2` 工作台设计

## 1. 为什么要做 `/v2`

旧页面是一个线性用户旅程：

```text
表单 -> 对话 -> PRD -> 接口文档 -> 提示词
```

它适合新用户，但不适合以下情况：

- 已经有 PRD，只想继续生成接口文档
- 已经有 PRD 和接口文档，只想生成提示词
- 希望中途返回上一步
- 希望刷新后继续工作

所以 `/v2` 被设计成一个**工作台**，不是单一页面。

## 2. 当前支持的入口模式

### 2.1 `structured`

从结构化需求开始：

```text
结构化录入 -> 澄清 -> 回填 -> diff -> PRD
```

### 2.2 `prd`

直接贴现成 PRD：

- 进入 PRD 审核页
- 直接生成接口文档

### 2.3 `prompts`

直接贴 PRD，选填接口文档：

- 进入当前阶段
- 直接生成提示词

## 3. 当前支持的阶段

`/v2` 目前有这些 ViewState：

- `form`
- `chatting`
- `generating-prd`
- `review-prd`
- `generating-api-docs`
- `review-api-docs`
- `generating-prompts`
- `review-prompts`

## 4. 阶段导航

工作台顶部现在有显式阶段导航：

- 结构化需求
- 澄清对话
- PRD
- 接口文档
- 提示词

它的意义不是装饰，而是：

- 当前在哪一层，用户一眼能看见
- 哪些阶段已经完成，可以回退
- 哪些阶段尚未可达，不能误点

## 5. 工作台为什么比传统页面更合适

因为 skill-first 设计天然是多阶段的。

如果没有工作台，用户会被迫：

- 永远从头开始
- 一旦中断就丢失状态
- 很难验证中间态
- 无法把“结构化摘要”作为第一类对象来看待

## 6. 当前已经支持的工作台能力

### 6.1 本地状态持久化

当前 `/v2` 已把以下内容持久化到 `localStorage`：

- 当前阶段
- 入口模式
- 表单内容
- 结构化摘要
- 对话
- PRD
- 接口文档
- 提示词
- 手动输入内容

### 6.2 可中断

任意阶段都可以：

- 返回上一步
- 结束当前任务

### 6.3 可跳步

只要已有内容，就可以从中间环节进入。

## 7. 这对 skill 系统意味着什么

`/v2` 不只是一个前端页面，而是 skill 运行时的一部分。  
它承担的是：

- 输入结构化
- 中间态可视化
- 用户确认
- 流程控制

这让 skill 的执行过程不再是黑盒。
