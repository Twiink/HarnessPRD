# Skills 方案总览

## 1. 这套方案是什么

VibeCoding 的新一代方案，不再把“生成 PRD”理解为一个单独的 prompt，而是把它定义成一个**可复用、可迁移、可验证的 skill 能力包**。

这个能力包的目标不是只服务某个模型，而是服务一个更稳定的问题定义：

> 输入一份结构化的产品需求摘要，必要时通过澄清对话补齐缺失信息，输出稳定、结构化、工程可执行的 PRD。

这意味着系统不再只是：

```text
用户输入一段话 -> 模型自由发挥 -> 生成一份文档
```

而是升级为：

```text
结构化录入 -> schema 校验 -> 澄清对话 -> 结构化回填 -> diff 确认 -> PRD 生成 -> API 文档 -> 提示词
```

## 2. 为什么要升级

旧模式的问题主要有三类：

1. 输入不稳定  
用户可以用任意方式描述需求，模型需要先猜测结构，再生成 PRD。

2. 输出难约束  
Prompt 再长，也很难完全防止模型遗漏、重复、编造或格式漂移。

3. 能力难复用  
一旦逻辑被写死在某个 Prompt 或某个 Agent 平台里，就很难迁移到别的模型或运行时。

新的 skill-first 方案要解决的正是这三件事：

- 输入先结构化
- 流程显式化
- 能力模块化

## 3. 这套方案的核心组件

| 组件 | 作用 |
|------|------|
| `skill.yaml` | 定义能力契约：输入、输出、约束、工作流 |
| `instructions.md` | 定义 skill 的执行步骤与写作规则 |
| `references/` | 放模板、schema、示例、规则文件 |
| `/v2` 工作台 | 负责结构化录入、澄清对话、回填、diff 和多阶段跳转 |
| `document_service.py` | 负责 skill 文件加载、文档生成、摘要回填 |

## 4. 为什么叫 skill，而不是 prompt

因为这套能力的本质已经不只是“让模型说一句话”，而是一个完整的可消费单元：

- 有输入协议
- 有输出协议
- 有参考文件
- 有中间态
- 有验证逻辑
- 有失败处理
- 有跨平台可迁移性

Prompt 只是 skill 的一部分，而不是 skill 的全部。

## 5. 这套方案现在已经具备什么

当前仓库里，这个能力已经有了第一版落地：

- 通用 `prd-generator` skill 包
- `/v2` 结构化工作台
- 澄清对话专用系统 Prompt
- 对话回填 `requirements_summary`
- 回填 diff 预览
- PRD / 接口文档 / 提示词串联
- 从中间步骤直接开始
- 本地状态持久化

## 6. 这组文档会讲什么

后续文档会逐步解释：

- 为什么 skill 要做成平台无关
- 目录和文件怎么组织
- 前端字段怎么映射到 schema
- 为什么需要“回填而不是直接生成”
- JSON 回填为什么经常失败
- 怎么兼容 Claude / OpenAI 等不同模型
- 为什么这套设计受 OpenClaw 风格启发，但并不绑定 OpenClaw
